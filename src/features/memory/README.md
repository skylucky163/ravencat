# 记忆系统 Feature

Memory V3 已接入生产。产品契约见 [实施规格](../../../docs/memory-simplification-v3-implementation-spec.md)，代码定位见 [引用索引](../../../docs/memory-simplification-v3-reference-index.md)。

## 产品入口

- /memory：AI×用户空间以星球呈现，点星球打开记忆／触发词面板，正文列表按需渲染。新建／编辑、触发词关联详情与右上角设置均通过 App 适配为独立 Expo Router 页面。
- 单条正文最多 500 个 Unicode 字符，去首尾空白；不自动缩句、拆分、摘录或建立来源关系。
- 独立摘要选填、最多 50 个 Unicode 字符，不占正文额度；摘要与正文都参与字面检索、触发词关联和向量化。迁移107只给旧记忆增加空摘要，不改写正文、时间、revision 或已有向量。
- 协议空间可单向转存到当前 AI 的记忆空间。Host 用同一事务创建正文／摘要与向量待处理状态并删除原协议；失败全部回滚，commit 后再通知 UI 与 embedding worker。转换后不再常驻注入，没有来源联动或反向转换。
- AI 拆开记忆工具包后，可用 `convert_exited_group_history_to_memory` 将自己已退出群聊的冻结摘要和聊天正文交给当前 AI 的聊天模型提炼，保存为不超过 500 字的独立记忆，摘要标题固定为「【群聊·退出时群名】」。不提供未加入群的目录；仍在群内时返回无法使用。过程记录不进入模型来源，不自动截断、重试、删除历史或切换历史注入。模型完成后，Host 在同一事务中检查退出快照仍有效并创建记忆及向量任务；同一退出记录重复转换返回已有记忆，不覆盖后续编辑。用户入口仅保留历史查看和注入开关；转换后可用 `update_memory` 二次整理。
- remember_memory／recall_memory／update_memory／forget_memory 复用唯一 Agent Runtime。空间、run 和新建幂等键来自可信执行上下文；更新工具按记忆 ID 复用正文编辑命令，保留记住时间并自动更新向量。
- 被动召回只匹配本次输入；主动检索 lexical 优先、vector-only 补充，完整排序后固定 run 内队列并分页。
- 触发词以关联组管理：一次输入的多个词保存为一组，可同时选择同空间的一条或多条记忆，支持 1:1、1:n、n:1、n:n。词只在组内按规范化去重，跨组允许重复；命中任一词即带入本组开启的记忆，多组、多词命中按记忆 ID 去重。列表展示完整词集合与关联数量，详情可编辑词集合、添加记忆和维护组内关系开关。
- 新组默认只关联手动选择的记忆，可按组开启“正文或摘要包含任一词时自动关联”。手动关系在正文修改、再次启动和备份恢复后保留，删除任一端时清理；关闭一组的关系不影响其他组。117 升级将旧触发词逐条转成保留原 ID 的单词组，继续开启自动文本关联，保留旧手动关系和关闭事实，不自动猜测或合并旧组。
- embedding 可选。开启时正文或摘要编辑自动重建，模型指纹＋内容 revision＋claim 由 Repository 原子比较；自动最多三次，终态可在详情手动重试。Host 对同一轮连续任务的终态失败只提醒一次，已有失败提示未关闭时不追加相同弹窗；逐条原因与手动重试仍由记忆条目保存。关闭或没有可用模型时照常保存、编辑、按关键词检索和通过触发词自动带入，不发出向量请求。更新工具省略摘要时保留，空字符串时清除。
- /memory/settings 集中提供召回数量、通用「记忆向量化」开关和独立模型选择，首页不再重复展示模型入口。开关关闭时仍能选择和管理模型，开关与模型都保存在 Memory 自有 `memory_model_settings`，全部空间共用。新安装默认关闭，新增或完善辅助模型不会自动开启；152 升级按旧实际模型选择保留启用状态和引用，未选模型的旧库保持关闭。配置管理统一从辅助模型中心的向量化入口进入，选择弹窗不带管理跳转。
- 普通关闭保留模型与已有向量；切换模型、修改所选模型的连接配置或重新开启不会自动为历史记忆重建向量。切回未变化的旧模型时，只要保存向量的模型指纹与正文／摘要 revision 仍匹配，就直接恢复使用并恢复索引维度，不发请求。已被新结果覆盖、已清除或内容已变化的旧向量不能接管。
- 每条记忆在列表和详情均可单独请求向量化，包括未请求、失败或已就绪条目；只提交该条已保存的正文／摘要，不强制保存草稿、关闭页面或重建整个空间。应用先解析当前可用模型，再以发布 revision 保护单条请求；Host 复用维护边界取消并等待旧执行，Repository 撤销中断遗留的整批发布资格。任务模型／内容版本与已保存向量的来源版本分开维护，失败或取消不会把旧向量误标为新模型的产物。正在等待的同一条任务不提供重复点击入口；关闭向量化或未配置可用模型时不能请求。
- 开启时新增／编辑仍只生成对应条目的向量；用户也可在设置中确认「重建全部记忆索引」。新向量暂存内存，全部生成成功后，Repository 在同一事务验证模型、持久发布 revision、任务 ID 和完整正文版本快照，再一次性替换。网络失败、取消、内容变更或 SQL 错误不会发布半套索引；退出应用丢弃未发布的新结果，重新重建不会自动恢复 API 请求。Host 维护边界负责取消、等待及前后台／reset 收口，模型资产的更新事务同步撤销旧发布资格。
- 独立红色「清除已有记忆向量」经确认后主动清空全部空间的向量与任务状态，保留开关、模型、正文、摘要、触发关系和召回设置。清除撤销 claim 与整批发布资格，不立即重建。
- 聊天原文与两级摘要由 Chat 独立拥有；记忆工具包提供 search_chat_messages 按关键词回查仍保存的聊天原文，包括已被摘要的消息；read_chat_message_context 按消息 ID 读取附近上下文，前后各默认 3 个消息气泡、最多各 10 个；search_chat_summaries 查询摘要、edit_primary_summary 编辑单条一级、delete_primary_summary 删除单条一级，以及 get_secondary_summary 读取完整二级正文、edit_secondary_summary 局部或整体替换二级正文。两级编辑都支持局部与完整替换，一级删除匹配查询时的完整正文。身份来自当前 AI，只访问自己的单聊与仍参加的群，不复制成 MemoryEntry。两级独立维护、支持关闭与整批 token 归纳，当前产品契约见[对话两级摘要](../../../docs/architecture/chat-summary.md)。

## 所有权

群成员正常回复接通既有 Memory 工具，仍只操作当前 AI 的记忆空间，授权及工具自身限制不变。跨会话聊天原文／摘要属于 Chat 的主客上下文查询，不复制进 Memory，也不因客读取改变摘要处理进度。

domain 定义正文与排序规则、Repository port；application 拥有用户命令、查询、召回队列及 embedding use case。SQLite adapter 只通过 databaseCoordinator 提交事实。

index.ts 暴露稳定命令／查询／DTO／UI／工具；composition.ts 仅供 Host 装配具体仓储、模型端口和后台任务。Host 的前台队列处理唤醒、取消、reset／restore quiesce，业务状态仍在 Memory。

旧主题树、草稿、管理员、会话粘连、近期胶囊、来源关系和 F7 独立检索路径均已退出。尾部升级定向清理退休数据与绑定，不删除通用模型资产或其他 Feature。

## 星空呈现与资源预算

`presentation/MemoryGalaxy.tsx` 只拥有视觉交互，复用现有空间查询与选中命令。首页快照通过 Memory Repository 一次聚合所有空间的真实正文数量，只为当前空间读取正文、触发关联与召回设置。默认空间详情在开屏期间准备，打开或收起同一空间面板不重复加载；切换到另一空间时保留星空，过期请求不能覆盖当前详情。Host 枚举空间复用助手身份摘要，不读取完整模型配置后再逐个重查助手。选择偏好只持久化最近空间，不广播记忆变化或唤醒向量队列。每个星球周围的星星数量为 `max(1, min(10, memoryCount))`，只是视觉映射，不限制正文数量；增删记忆后复用已有事实订阅刷新。`MemorySpacePanel.tsx` 使用 FlatList 管理正文与触发词，导航仍由 App 适配。

玻璃主题下，`MemoryScreen` 为当前页面注册独立玻璃场景，直接采样同一棵星空、星球与页面内容视图树；面板继承该场景，不采样全局壁纸。面板和开屏层位于采样源之外，避免递归采样，星空上的触摸与无障碍入口保持可用。面板文字使用共享深色主题的文字色，保持深色星空上的可读性。

`shared/ui/space/GalaxyBackground.tsx` 与主动伴随共用，将本地 Hubble 星云照片以静态色彩矩阵转为低亮度蓝紫色尘埃。Android SVG 滤镜会分配、复制多张画布大小的位图，因此尘埃纹理最长边限制为 512 物理像素，再通过视图变换放大到视口，避免入场时处理多张全屏位图。纹理以 90 秒周期漂移并轻微明暗变化，远星与暗角保持完整视口精度、不随纹理移动；静态主题染光与 3 条远星／微尘路径不随屏幕面积增加图元。

`MemoryGalaxy.tsx` 拥有天体素材分配：中心主星使用海王星，其余从火星、木星、水星、木卫二、木卫三的本地影像中选择。每页最多五个外围空间，按身份排序、散列和页内占用分配五种图片，确保当前组无重复；刷新或增删记忆不会换图。跨页可以复用素材，不把有限图片种类当作空间数量限制。

`MemoryPlanet.tsx` 只渲染装配提供的图片及校准取景，保留真实云带、地表、冰纹和坑纹，删除单张海王星换色、程序颗粒与模拟坑纹。主星保留较鲜明的蓝色，其余适度降低饱和度与亮度，保留各自地貌和原图色彩差异。所有球面统一叠加左上方受光、右下方夜面，大气只绘制窄的受光弧；不使用整圈呼吸光晕。记忆星星是淡白光点，错相改变亮度，主星周围适当放大；星点层以 45 秒周期绕各自球面转动，球面和名称保持方向，不使用十字闪光。环绕时钟及暂停／恢复由 MemoryGalaxy 统一拥有。图片来源与署名见 [素材说明](presentation/assets/README.md)。

主理空间固定在中心，每页展示最多五个环绕空间；没有主理身份时首个空间作为视觉中心。主星直径 96，单空间时为 116；其余按真实记忆数量对数映射到 32～44，再按空间远近轻微改变尺寸与明暗，尺寸上限不限制记忆数量。不绘制轨道线；主星不公转，其他星球以三分钟周期沿椭圆路径移动，名称始终正向。拖动／缩放作用于整个星系，初始状态和复位完整展示当前组。近景仍只有 28 个星点，分为 3 层闪烁，轻触期间才计算避让；同时最多绘制 6 个空间、60 颗记忆星星。动画在 Reanimated UI 线程执行，只更新 transform、opacity 和景深层级，不逐帧更新 React state、重新计算材质或实时模糊星云。

Screen 统一拥有装饰动效的生命周期：页面失焦、应用后台或面板打开时取消星空动画并停止流星计时器。开屏分为固定开场、静止准备、就绪后淡出：开场播放期间不挂载星空；开场完成且快照返回后才挂载，等待页面布局后再淡出，不用固定时长推测加载完成。开屏期间不同时播放星空，开屏光点尺寸有界；系统减少动态效果时跳过开屏、闪烁、自转、避让与流星。流星仅更新 transform 和 opacity，离开页面时取消未完成动画。

`shared/ui/space/starField.ts` 用固定种子独立采样位置、尺寸与亮度，避免等差坐标造成整齐斜列。远星、微尘和近景分开采样；刷新、打开面板或改变视口不会重新洗牌。

流星由 `shared/ui/space/ShootingStars` 与主动伴随共用：Screen 只提供前台可动效状态，共享组件拥有稀疏生成计时器和单条飞行的清理，不在两个 Feature 中复制计时与飞行流程。

性能预算是实现上的开销限制，并非各机型帧率承诺；正式流畅度、功耗仍需 Android 真机测量。

## 验证

`node scripts/verify-memory-glass-scene.mjs` 验证面板打开、关闭与再次打开时采样当前记忆页、交互与无障碍入口、页面实例的场景隔离、普通主题的表面和文字色，以及默认详情复用、过期请求隔离、数据与开场不同完成顺序下的布局就绪、不同屏幕密度下的星云像素预算。

npm run verify:memory 在隔离 SQLite 验证正文／摘要边界、空间隔离、幂等、关联组的多对多与同名词、组内开关、冻结分页、向量 CAS／三次上限、摘要交接／用户维护、第二次启动及 V3 快照恢复；也验证旧触发词迁组、旧记忆摘要迁移与协议转存的事务回滚、并发唯一成功和过期快照拒绝。另验证真实 Prompt 组装的旧预设、稳定前缀和无裁剪行为。npm run verify:database-baseline 覆盖 108／116 的生产升级入口及失败回滚。
