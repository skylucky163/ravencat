# Calls

通话文字草稿由本次 `CallMediaRuntime` 持有，输入弹窗只展示和编辑；关闭弹窗、切换小窗或重建页面不清空文字。文字提交在用户转写事实落库后清除对应版本，AI 回复失败不恢复已发送内容，语音输入不消费文字草稿。通话终态清除草稿，不跨通话或进程保存，也不转存到聊天草稿。

「对话设置 → 通话铃声」按 AI 分别保存来电铃声与拨出等待音，支持本地音频、10 秒试听和恢复默认。音频在原生边界确认可播放后，经 MediaAsset 同事务提交选择与 revision CAS，参与备份、共享引用回收及角色级联删除；选择器缓存不承担长期存储。

来电发布通知后由原生铃声 owner 循环播放，通知本身静音以免双响；接听、拒接、未接和撤销通知统一停播。声音沿 Calls 提供的响铃窗口限定原生资源寿命，不提交第二份未接状态。来电遵守系统静音、振动与勿扰；拨出等待音使用通话音量，由 CallExecutionService 持有，接通申请 Telecom 前和释放/销毁时停止。自定义拨出音频使用通信音频属性，与默认拨号音的音量通道一致，不使用可能映射到 DTMF/媒体音量的 SIGNALLING 属性。试听使用媒体音量，页面失焦、App 切后台或真实呼叫接管时停止，不能抢占真实呼叫。媒体读取/播放失败报告错误或诊断，不替换用户选择的文件。

AI「更多 → 通话记录」列出功能启用后已接通且结束的电话，按发起时间倒序展示。Calls 在创建会话的事务中分配本地日期时间标题，同一 AI 的标题唯一；改名先规范 Unicode 和空白，再在事务内查重并依赖唯一约束裁决并发。历史详情使用主题默认背景，双方显示当前用户姓名和 AI 昵称／公开名称。语音条复用共享 `AudioPlaybackBar`，不引入聊天气泡；逐条进度订阅留在条内，列表卡片关闭原生玻璃，不挂载实时媒体 Runtime。

聊天与通话历史共用 platform 的本地音频播放 owner，包含暂停、继续、互斥与晚到回执收口。Chat 仍独立拥有消息已播放标记，通话历史回放不修改聊天消息。记录页失焦、退出或接通新电话时只释放本页 scope 的播放，不停止已由其他页面接管的音频。

`call_history` / `call_history_entries` 拥有历史展示；用户转写与展示行同事务提交，区分语音和文字输入。实时采集在原生缓存写 PCM，按 ASR 的毫秒时间范围导出 WAV，不把整通电话积存在 JS 内存。已接受的语音立即进入唯一用户回复入口，导出失败仍保留转写。TTS 在原有串行队列逐句保存合成音频，不重新合成，不合并为整轮语音；打断后的排队句子继续作废。采集原始暂存和合成临时文件仍由各自媒体 owner 收尾。

原生采集层使用 WebRTC VAD（AGGRESSIVE 模式）逐 20ms 帧判断人声，连续 160ms 人声后通知 Calls 声学候选，持续人声的重复通知间隔为 800ms；不再按音量峰值和采集块数猜测用户开口。候选只放行 ASR 识别结果，不能独自停播；STT 开始或中间结果产生非空文字后才打断 TTS，只有最终结果的提供方仍走统一用户输入入口。空识别结果不打断，插话时延包含识别等待。VAD 按录音会话创建和释放，跨采集块保留未满帧的 PCM；ASR 与归档仍接收完整音频。Calls 的 AEC 可用性与回声隔离规则仍由 `CallSpeechDuplexGuard` 持有。`SpeechActivityDetectorTest` 覆盖分帧、持续确认和通知间隔，媒体生命周期测试覆盖声学候选、空识别与非空识别的打断边界；真实环境的误打断和免提回声仍需真机验收。

录音通过 MediaAsset 保存到应用私有持久目录，元数据与业务引用同事务提交，纳入备份、共享引用裁决以及角色/会话级联删除。手动删除历史只删除展示和媒体引用，不撤销 `call_events` 或已有 AI 摘要；共享资产在最后一个引用消失后回收。记录页按 AI 提供「保存 AI 获取的截图」开关，默认关闭；开启后只为之后的截图创建独立 MediaAsset 和 `call_history_images` 引用，详情可查看并单独删除。关闭不删除旧图，视觉临时快照仍按原生命周期清理；永久副本不依赖其 URI，也不录制整段视频。升级不补录旧电话或已经清理的音频。`verify:call-history` 覆盖这些持久化行为，原生 `SpeechSegmentArchiveTest` 验证分段 WAV 与暂存清理。

应用设置工具可按 AI 获取、更换或恢复通话背景，各 AI 只管理自己，当前主理 AI 可管理其他角色。图片准备在事务外，提交沿用 Calls 背景 revision CAS；权限与执行资格由 Host 装配进同一事务。背景及资料提交事实刷新已运行通话的 React 展示，不改变原生通话启动时的身份快照。完整契约见[应用设置工具](../../../docs/application-settings-tools.md)。

Calls Repository 是通话会话、事件与附件的唯一业务真值。`AICallRuntimeService` 在提交状态后更新消息时间线和原生投影；接听、拒接、去电决策和挂断通过 Repository CAS 提交，晚到决策不能复活终态。

接听先领取 `connecting`，系统音频就绪后才提交 `active`、接通时间和接通标记；等待系统端点不算通话时长。音频建立失败显示「通话未接通」，以系统异常自动结束记录；连接期间挂断后，迟到的音频就绪回执不能发布接通状态或开场白。

`AICallRuntimeService` 同时维护接通期间的内存标记：active 提交后设置，终态提交后按通话 ID 清除。Chat 经 Host 注入的快照与订阅同步输入框，发送、重试及分享读取同一标记，不轮询 SQLite；标记不承担持久并发裁决。冷启动复用已有通话恢复查询补齐，恢复期间的新生命周期提交优先，页面卸载和切后台不清除标记。

启动恢复先按通话 ID 查询原生执行宿主；页面重新挂载而宿主仍存活时，不提交故障终态，也不回收该通话快照。重复挂断已是终态的通话仍释放媒体并完成 业务终态等待，只保留首次终态事实，不重写结束原因、状态气泡或重复触发跟进。

通话共用应用唯一 RN 后台身份，媒体服务在总开关关闭时继续持有同一身份至通话结束，不创建逐通话 RN task。持续执行入口位于 Host：`executeCall` 先等待备份恢复和普通 SQLite bootstrap，再创建唯一 `CallMediaRuntime`，等待通话终态、输入退场和命令回执后释放原生宿主。媒体仍复用统一用户输入、Call reply run、TTS 队列、ASR 与快照持久化链，没有独立后台回复流程。

`modules/call-runtime` 持有每通电话的媒体前台服务、Core-Telecom、音频 endpoint、CameraX 和系统通话窗口；CPU 执行期向 `background-runtime` 登记，其他任务结束或关闭通用保活不会释放正在通话的登记。`call-audio-playback` 只播放音频。悬浮权限仅控制窗口，通话执行不依赖 RavenCat 悬浮球或 Companion 服务。

AI 来电邀请先通过应用通知与铃声展示，用户接听后才注册 Telecom；用户拨出的系统通话同样在 AI 接听后注册，因此收到来电邀请不代表系统音频已激活。原生激活有整体期限，失败由原生直接断开；终态音频释放立即断开系统会话，不拖到 通话输入退场后。系统结束动作立即归还平台回执，业务命令独立等待，避免 JS 收口反向等待系统回调形成环路。新通话等待旧系统会话与服务释放的共同结果，正常进行中的通话仍按业务占线规则保护；具体期限与设备验证见原生通话契约。

来电响铃只有原生 `IncomingCallActivity` 一份接听/拒接界面。应用在前台时由通知模块直接展示它，不等待系统全屏通知；后台或锁屏时继续由系统通知与 FSI 负责。前台展示与通知点击共用相同 Intent 和动作处理，不复制业务接听流程。

来电 CallStyle 通知始终携带全屏入口，这是未使用 FGS 的系统发布契约，前台直接展示不能将它移除；用户关闭全屏展示时由 Android 裁决通知形式。通话链路失败写为系统提示，不归入 AI 或用户的普通发言气泡；未应答、拒接和通话时长仍按发起方展示。

Expo bridge 的生命周期回调是线程边界：前后台变化与 React 销毁都交给主线程处理窗口、CameraX 与执行清理。销毁清理不依赖随后取消的模块 scope，并按 ReactContext 身份只释放该实例的通话。通话执行期间通过共享 Overlay 可见性契约抑制普通悬浮球，结束后释放抑制；不改变小球开关，不停止 Companion 或悬浮球 Service。

`CallRuntimeProvider` 只订阅媒体状态并投影当前页面展示意图；页面卸载不会释放媒体。摄像头使用通话 Service 持有的唯一原生窗口，不再挂载 React 页面预览或切换 surface。返回地址由 Host 提供，Feature 不执行 App 路由。

通话页进入终态立即退出，不展示结束页，也不等待媒体清理。退出由 `CallScreen` 统一发出一次，挂断按钮只提交业务动作；应用执行宿主继续等待资源释放。来源属于本次展示：Host 在通话收起期间更新最近的 App 内完整地址，小窗深链再次进入后返回这次的来源页及其参数；同次展示的 Activity 重建保留该来源。`android-overlay-runtime` 的 `CallPresentationReturn` 由主界面生命周期、原生来电壳及通话小窗共享；小窗在每次拉起 App 之前重新捕获主界面是否可见。来自桌面或其他应用时，退出先把本应用任务退后，再整理 App 内路由；不主动启动其他应用，也不沿用首次拨号或接听的来源。

深链和开发重载恢复通话地址时，Host 先等待数据库就绪，再读取该通话并复用 Calls 的页面准入判定。已结束、已删除或仍由原生来电界面独占的通话不进入 RN 媒体等待页，沿既有退出路径返回；路由卸载会取消本次准入结果的消费，迟到查询不会重新激活旧页面。该检查只属于外部路由边界，不创建媒体 runtime，也不改写通话事实。

用户文本和 TTS 按句事件在 Repository 提交后发布内部事实，媒体状态立即追加字幕，不等待整轮 AI 回复或轮询。歌词流只从这些正式事件生成 AI 行，保留历史句、贴底跟随与翻历史时停止跟随。

实时回复每轮固定角色 TTS 模型，并使用 Speech 的厂商文本契约生成提示词、验证流式句子。合成输入保留当前模型允许的声音和停顿标记；通话记录、播放事件与字幕使用无标记的转写。分句不切断跨 delta 标记；句间显式停顿与两侧正文保留在同一合成单元。模型配置变化只影响下一轮，播放队列不再次解析或验证句子。具体支持范围与邀请开场白的纯正文边界见 [Speech README](../speech/README.md)。

实时通话复用 Host Agent 与普通单聊的 Registry、工具包、MCP、参数校验、预算及取消链。Host 按当前 AI 授权、主理身份与通话场景提供工具；通话不暴露再次来电、普通消息发送及依赖 Chat 媒体提交的工具。每次模型回合的正文都逐句朗读，思考和工具结果不朗读，完整正文仍由 Calls 提交一次。工具执行期间显示“正在使用工具…”，结束后按尚在生成或播放的实际状态恢复。

AI 主动挂断使用精确的 `[[END_CALL]]` 控制信号，不依赖工具开关。Calls 在语音解析前从本轮任意位置提取标记，支持跨流式分片；标记不进入合成、字幕或转写，告别语播放完后仍由通话回合 owner 提交终态。其他语音标签继续由 Speech 验证。

`lookAtUser` 将本次快照经现有视觉路由转换成文本观察与 `modelImages`，复用统一 Agent history 续答；不再另建工具循环或读取历史“最新帧”。视觉输入读取后即释放本次快照，失败和取消同样清理，OCR 事实继续保留。

通话小窗使用 112×150 的竖向比例。开启摄像头后，通话页、其他页面和 App 后台保留同一个窗口、位置与预览；关闭摄像头时，后台小窗在同一区域显示 AI 头像并以黑色补足空白。单击没有动作，完整双击松手后返回通话页；整块画面超过系统触摸移动阈值立即拖动，不等待长按，也不同时触发双击。窗口坐标使用完整屏幕范围，不裁状态栏、挖孔或键盘区域。摄像头权限之外需要悬浮显示权限；镜头翻转在通话页控制区操作，挂断仍可从通话页或持续通知直接执行。

双击恢复时，页面数据、背景图片和布局就绪后，`CallPresentationSurface` 按原生帧时钟让实际页面原地淡入。系统小窗在准备与交接期间始终保持原坐标和 112×150 尺寸；摄像头预览保持可见，关闭摄像头时的头像小窗在原位置同步淡出。真实页面完整绘制后才移除头像小窗，不按路由状态或固定延时提前移除。过渡不截图、不移动头像、不扩缩窗口；切后台、页面退场、相机模式变化及权限撤销结束当前过渡，旧绘制回调按恢复批次隔离。

头像由宿主从 AI 资料传给原生服务，只读取一次并共享给小窗与持续通话通知，独立的全屏通话背景仍由 Calls 设置管理。用户挂断后的 AI 跟进仍严格解析 JSON；不合法输出报告失败且不交付为聊天消息，不影响已经提交的通话终态与资源释放。

通话错误显示失败阶段及具体原因：接听决策、模型回复、回复语音文本解析、TTS 合成/播放、STT 识别分别标识，不用聊天的通用错误提示覆盖服务端信息。HTTP 状态、Provider 错误码与描述沿传输边界保留；错误提交后立即投影，点击通话页提示可展开并选择复制完整详情。用户拨号失败时由聊天发起入口展示全局错误详情，退出通话页或聊天已有消息不影响查看；已取消、接通或 AI 明确拒接不当作系统故障弹窗。取消与用户打断不作为故障显示。

原生音频建立失败保留注册、激活、等待可用端点、等待当前端点或初始路由确认的失败阶段，并附设备/API 与端点类型；业务收口前保存为正式错误事件，用户已挂断引起的取消不记为故障。「通话记录 → 对应记录」从最近 200 条事件中展示异常，空对话记录也可展开详情并长按复制时间、通话 ID 与完整原因。该查询只读，不补写旧版本未记录的信息，也不要求用户抓取系统日志。

用户拨出时只请求一次接听决策，模型直接返回口语及 `[[接听]]` 或 `[[拒绝接听]]`。模型边界识别任意位置的精确标记，抽离全部同种标记后，将正文交给首句字幕/TTS 或拒接聊天回复；不再要求 JSON。只有标记也执行对应动作，没有正文时不制造空字幕、空聊天消息或默认台词。缺少标记或两种标记冲突时不猜测意图，用户看到未接通提示，具体原因留在诊断日志。提示词定义保留已持久化的旧 ID，名称和正文更新为标记协议，已绑定的 2.x 预设继续引用同一个受保护定义；页面和 TTS 不重复解析。

接通后每次稳定转写或文字输入触发回复，工具调用可产生模型续轮；用户挂断已接通通话还可能触发既有跟进决策。TTS 按句合成，STT 使用实时识别连接，两者请求与文本模型独立。「小程序 → AI 工具 → AI 请求诊断」开启后记录后续文本模型请求及解析前响应，保留最近 10 次；诊断本身不增加请求，不覆盖 TTS/STT，也不会补录开启前的失败。

当前实现、验证证据与设备验收清单见 [原生持续通话实施清单](../../../docs/ai-video-call/native-call-implementation-checklist.md)。
