# Assistants 与辅助模型资产

配置表单由 `ThemedSurface` 统一拥有内容面的普通／玻璃材质，`commonStyles.formSurface` 只规定留白与圆角；输入与选择控件继续使用主题的 `surface.input`。服务配置、辅助模型、AI 新建与模型设置、群聊新建沿用相同的颜色层次，和 MCP 配置的内容面保持一致；整张表单只拥有一个玻璃表面，内部 Key 分组只染色，独立选择弹窗由自己的材质所有者负责；字段保留原有局部布局与错误定位。

STT、TTS、翻译与生图配置在创建时选择提供方，保存后固定；编辑只修改名称、同一提供方下的模型、凭据与参数。更换提供方需要新建配置，再由使用处显式选择。资产仓储在已有更新事务内确认身份不变，拒绝时不写部分字段、不创建服务绑定、不撤销消费者资格。语音和翻译的提供方初始化只服务新建表单；已有语音资产仅维护本提供方的参数集合，不保留跨提供方切换的 Key 延迟提交或恢复分支。

编辑表单统一按配置、连接、模型与参数分组，测试与删除位于末尾；连接区先显示 API 地址，再显示凭据，固定地址只读、自定义地址可编辑，地址与 Key 共用自动换行的输入基础。提供方与模型名称的字段标签、测试分组保持一致；禁用由控件样式表达，常驻区域只保留必要字段与真实错误。辅助模型 ID 字段复用 `ModelPickerField`，通过右侧箭头打开 `ModelPickerModal`，统一搜索、加载与刷新；支持手输的模型保留失焦保存，列表选择立即保存。候选查询与提交由页面负责，公共控件只负责展示和交互。`ModelFormSection` 使用 React 片段，只增加分组标题，不增加原生布局层，保持字段错误定位相对滚动内容的坐标契约。

`image_generation` 用途在辅助模型中心只管理模型资产，复用创建与自动保存。表单提供硅基流动、MiniMax、豆包 Seedream、阿里千问和 OpenAI GPT Image；供应商保存在现有 metadata，地址由预设固定，模型只能从已适配列表选择，不再提供自定义 OpenAI 兼容或能力开关，也不从通用服务选择任意地址。旧自定义资产保留原记录并明确不可用，需要新建供应商明确的配置，不在原 ID 下改换协议。新建阶段切换供应商清空旧 Key 和服务绑定，避免凭据跨供应商携带。表单不保存聊天采样参数或本次图片参数，也不提供配置检查或连接测试；创建与自动保存保留必要的字段校验，实际生图能力在「AI 生图」页面使用时确认。生图资产不参与首次模型初始化，也没有角色级选择；Media 在「AI 生图」页面保存实际使用的模型 ID，供用户与 AI 工具共用。

AI 个人空间封面由 Assistants 持有，个人主页与该 AI 的朋友圈顶部共用同一份图片，默认使用 `assets/stars.jpg`，用户朋友圈封面独立。`set_own_space_cover` 属于应用设置工具包，只接收 `media_asset_id`，始终以可信执行上下文中的 AI 为目标；包括主理在内的任何 AI 都不能通过此工具修改别人。封面在事务外居中裁剪为 2:1，引用保存于 `assistant_profile_covers`，与媒体资产同事务提交，沿用回合资格检查和 CAS。提交后发布既有助手资料事实，两处页面复用 `AssistantSpaceCover` 展示；媒体引用纳入备份、共享保护及角色删除回收。

应用设置工具通过 Assistants 修改公开名称和头像引用：各 AI 管理自己，当前主理 AI 可管理其他 AI。头像自动裁剪后按原引用 CAS 提交，名称按旧名称 CAS 提交；权限与回合资格在同一事务内裁决。公开名称不修改用户私有昵称或历史消息，提交后发布既有资料更新事实。完整工具契约见[应用设置工具](../../../docs/application-settings-tools.md)。

`get_own_space_cover` 无参数读取自己的个人空间封面，复用 Media 的视觉链路返回图片和真实媒体 ID；默认星空图与两处页面共用同一资源且没有媒体 ID。查询只读取封面引用，不加载模型连接或密钥，已选图片读取失败直接报告，不用默认图掩盖。

辅助模型中心首先提供「服务配置」列表，进入列表项后编辑；下方按摘要、向量化、视觉、STT、TTS、翻译用途管理模型。每个配置保存名称、共享地址和固定认证方式，其下可添加多个独立命名的 Key。名称留空时显示递增编号，删除其他 Key 不重新编号。新建表单默认只有配置名称、Base URL 和一个 Key 槽位，通过「＋ 添加 API Key」增加；其他认证方式折叠展示。列表与表单复用公共主题表面，说明收进顶部问号 helper。

已有服务选择与快捷填 Key 共用「选择模型连接」弹窗，按配置名称和地址显示可展开／收起的分组；配置名称与 URL 上下排列；展开后缩进显示 Key 名称和完整 Key，两者上下排列，只有具体 Key 行可点选。每次打开统一收起所有分组；选后显示「配置名称 · Key 名称」。摘要、向量、视觉、AI 翻译、自定义兼容 TTS、角色与群管理员继续通过原连接 ID 引用具体 Key，模型及任务参数仍由原 owner 保存。配置名称／地址和各 Key 使用独立的增量草稿；改地址影响组内所有 Key，改某个 Key 只影响它自己的引用。删除单个 Key 或整个配置均在同一事务撤销旧请求资格、解除对应引用并清空继承连接，保留角色、模型、选择、正文和历史数据。

固定提供方的生图与官方 TTS 在 Key 输入框同行提供「＋」，打开同一连接弹窗前按当前实际地址筛选，跨配置名称保留所有匹配分组。匹配只忽略首尾空白与末尾斜杠，不混用不同协议、域名或路径；语音地址复用 Speech 的站点与工作空间解析。选择时重读 Key 并确认地址未变，只复制凭据，不改提供方、地址、模型或参数，不指定源服务引用；保存继续遵循该用途原有的服务绑定契约。ASR 使用专用语音连接与认证，不提供通用 Key 的「＋」入口；火山 ASR 明确引导填写语音控制台的 API Key。腾讯云签名凭据不参与 API Key 填充。

服务列表提供默认开启的「自动保存服务配置」。配置有效保存时，同事务复用完整匹配的具体 Key，或收录包含一个 Key 的新配置；不只凭 URL 合并已有配置。关闭后新连接只保存在当前配置，不影响已有引用。用途页改连接只影响自身，连接测试不收录配置。原单连接写入入口已由分组和 Key 命令替代。STT、官方 TTS 和腾讯云机器翻译保留独立连接，不关联或自动收录通用服务。

摘要模型使用独立的 `summary` 资产；连接与参数变更或删除和 Chat 请求资格撤销共享事务，保留会话引用、正文和进度。共享服务修改也处理跟随角色与群管理员的摘要。迁移157原地转换旧通用模型，保留 ID 与参数，不让既有摘要引用失效。一次性应用上下文设置仍只复制四项数值。

路由为 `/auxiliary-models/services`、`/auxiliary-models/services/[serviceId]`，以及已有的 `/auxiliary-models/capabilities/[kind]`、`/auxiliary-models/models/[modelId]`，均注册在 Expo Router。导航由 App／Host 适配，Feature 不持有路径。所有模型选择弹窗共用 `ModelPickerModal`，问号紧邻标题、取消选择在列表底部，统一移除弹窗内的管理跳转；已保存模型的业务选择由 `ConfiguredModelPicker` 展示。

用途资产不再提供启停开关，按配置完整性与类型决定可用性。角色 OCR、TTS 只手动选择；全局业务的首次资产初始化按各 owner 契约执行，摘要与 Memory 不参与。后续新增不覆盖已有选择。验证见 `verify:auxiliary-model-runtime` 与 `scripts/verify-model-service-configs.mjs`。

角色模型设置与已有辅助模型编辑自动保存：文字失焦时提交，停输不保存；开关与选择立即提交自己的字段。
角色模型、视觉辅助模型和群聊管理员的 Temperature / Top P 使用公共 `SliderField`；连续拖动本地预览，松手提交最终值，保留手动输入和字段错误提示。
角色模型的 Temperature / Top P 留空表示使用服务商默认值；输入框保持空白，轨道保留但不显示数值填充与滑块，仍可直接拖动设置数值。新角色与角色模型页的「重置为默认值」均将这两个参数留空，已有明确数值不自动改写。空值经过保存、重读、连接测试及各场景调用后仍不写入请求。
辅助模型和群聊管理员的同名参数遵循相同留空语义；OCR、表情识别与时刻图片理解不自行补充采样参数。
角色模型页提供「启用思维链」：已支持的可切换思考模型在开关开启时明确开启思考，开关关闭时请求直接回答，不依赖服务商默认值。页面将正向开关映射到已有的 `disableThinking` 配置，既有选择的实际含义不变。非思考模型保持原样；选择随角色持久保存，聊天、群聊、通话和主动任务使用相同配置。思考参数由 AI Platform 转换，固定思考模型仍受服务商能力限制。
用户输入在表单边界转换为增量命令，保存确认不回填正在编辑的草稿。
校验与写入错误在页面内展示；返回先提交，未保存错误可修正或恢复已保存值。新建辅助模型仍需明确点击「创建」。
输入、提交及页面生命周期契约见 [模型设置自动保存](../../../docs/architecture/model-settings-autosave.md)，行为验证为 `verify:model-settings-autosave`。
AI 个人主页由 Assistants presentation 拥有，路由为 `/assistants/[aiId]`，可从聊天更多顶部的 AI 名片、单聊／群聊消息及朋友圈作者的 AI 头像进入；消息名称和正文不承担主页导航。顶部栏显示「AI 名称的主页」，主页使用该 AI 的个人空间封面作为全宽封面，圆形头像叠在封面下缘，下方居中展示「公开名称（专属昵称）」与最多两行的人设简介，没有昵称时只显示名称。页面底部固定「发消息」操作栏（inputBar 材质），回到该 AI 的聊天页；聊天页已在栈中时直接回退，否则用它替换当前页。名称／昵称后的编辑图标跳转到 `/assistants/[aiId]/edit`，名称、昵称、人设仍分开编辑并按字段自动保存，页面不设完成按钮，返回时由 App 的保存边界提交后离开。App 负责 Expo Router 跳转与编辑页返回拦截，Feature 只表达导航意图；主页、编辑页和朋友圈通过同一资料查询订阅读取助手，不切换聊天会话，资料提交事实继续刷新聊天头像与名称。
主页「朋友圈」进入 `/assistants/[aiId]/moments`，由 Moments 复用时间线、分页和用户互动，按助手不可变 `agentId` 在 SQL 分页前筛选作者。顶部显示该 AI 的当前展示名和头像，封面与该 AI 的个人主页共用同一份个人空间封面；不读取用户封面、不提供替 AI 发布或设置封面的入口。空列表仍可下拉刷新。主页以朋友圈为主要入口，模型设置、上下文设置、聊天摘要归入下方的 AI 管理区域。上下文入口为 `/assistants/[aiId]/context-settings`，摘要与更多共用 `/chat/[aiId]/summary`。模型页按助手 ID 独立读取，不准备聊天；视觉模型选择由 Host 装入既有插槽。对话、上下文与摘要由 Chat 共用只读目标会话边界。
聊天更多顶部的整张 AI 名片可点击进入个人主页，不另加主页菜单项，模型设置、对话设置和聊天摘要入口继续可用；旧 `/chat/[aiId]/model-settings` 与 `/chat/[aiId]/chat-settings` 只重定向到正式地址，不再挂载旧 Shell 设置页。普通返回回到实际来源，选择固定消息起点才显式进入目标聊天。全局服务配置和辅助模型资产管理保留应用设置入口。
独立上下文页维护条数、固定消息起点和历史群聊注入；对话设置用一行入口跳转同一页，并保留回复方式、多气泡回复与行动步骤／Token 用量显隐。流式与多气泡本轮不改变入口或行为；模型页只编辑调用配置，重置不影响对话上下文。个人主页和对话设置均沿用助手已有字段与命令；头像命令只更新头像。通用草稿确认复用 shared/ui，契约见 [个人主页与对话设置自动保存](../../../docs/architecture/conversation-settings-autosave.md)。

`npm run verify:assistant-settings` 验证主页入口、独立模型页面、正式与旧设置路由、目标会话与背景键、Host 插槽和提交事实到聊天的同步。

模型设置和本地伴随的主理 AI 任命入口共用 Assistants 提供的确认弹窗，统一说明唯一主理关系、权限边界、撤销后七天冷静期及伴随与未来日程的影响；确认后的业务操作仍由各入口调用同一任命命令。

撤销立即收回主理身份与全部主理特权，七天内禁止任命任何 AI。冷静期由 Assistants 的关系记录持有，不提供开发页面清除入口。只有被撤销的原主理 AI 可自主调用 `release_host_cooldown` 提前结束；解除同时清除关系及角色冷静期字段，不恢复主理身份。Repository 在同一事务按调用者、有效期及当前普通身份裁决，操作与任命／撤销共用 authority lane。

Host 在模型运行准备时仅向该 AI 暴露已授权的解除工具；提示词中心将它放在「主理 AI 专属」中，仅冷静期对象可见和配置。AI 身份池在冷静期内向所有 AI 标注「已被移除主理ai身份，当前处于冷静期」，不提供剩余时间；到期或提前解除后不保留旧主理标签，也不清除真实聊天与摘要。本人每轮在历史之后的 AI 当前身份状态中读取剩余天数、结束时间和任命限制，不读取调用指引；自主解除的同意规则只由已授权的工具 schema 提供，状态块不依赖工具权限。

任命与撤销提交后通过 Host 网关唤醒 `HostRelationshipReplyTask`。原生 Headless 宿主持有完整执行期，Host 读取最新身份配置并复用 Chat 的 `requestProactiveChatReply`。用户操作通知作为本轮 system 中的应用触发资料，明确不是用户口述，不持久化为用户消息或系统提示条；保留历史末条真实用户消息。回复与工具权限、存档和消息交付沿用已有链路，不修改 canonical `user_reply` 游标或补建任务队列。唤醒失败不回滚关系，不用页面执行兜底。行为验证：`node --no-warnings scripts/verify-host-cooldown.mjs`。

用户昵称在 AI 个人主页中跟随公开名称展示，在独立编辑页中单独修改；仅用户可修改，空值恢复显示公开名称。`name` 是 AI 公开名称，`nickname` 是用户私有备注，用户界面通过 `getAssistantDisplayName` 解析。Host 只将当前备注放入前置身份背景；每次实际修改由 Assistants 读出事务内前值，Host 将设置更新与 Chat 操作事件组合在同一事务提交。Chat 负责事件正文、原时刻排序、提交后通知，以及后续窗口与摘要消费；不再追加一次性改名提醒或在成功回复后确认。其他 AI 的目录、群成员模型上下文与朋友圈工具继续使用公开名称；用户结构化 @ 在模型投影时按稳定成员 ID 转回公开名称。

`node --no-warnings scripts/verify-assistant-nickname.mjs` 验证昵称保存、清空、原位历史、窗口与摘要、并发前值、历史失败整笔回滚，以及群聊和朋友圈的名称隐私。

角色模型设置可弹窗选择角色 TTS，选择持久化于 `assistant_voice_settings`，用于该角色的语音消息和通话。新增角色默认不绑定 OCR、TTS，创建或补全辅助模型也不自动回填；已有选择保留，用户可独立更换或取消，任务解析不继承默认。

Memory、Chat、Speech、Integrations、Sticker 和 Moments 各自保存实际模型选择，只引用资产 ID，不复制连接信息与密钥。STT 列表直接嵌入 Speech 的语音识别模型选择控件；翻译列表嵌入 Integrations 的聊天翻译模型选择控件，AI 与腾讯云配置共用列表和选择。两者都在列表内选后立即保存，无单独设置页。
公开资产解析 `resolveAuxiliaryModel` 与选择投影 `getAuxiliaryModelSelection` 共用可用性规则，没有全局默认分支。
Host-only 的角色语音设置装配通过 composition 出口连接；UI 不直接访问 Repository。

全局业务的首次资产 ID 与完成标记保存于 `auxiliary_model_initial_defaults`，由 Assistants 持有，删除资产不清空 marker。未完成的首次配置暂不初始化，后续可用时只生效一次。升级保留已有业务选择，角色创建不消费首次资产记录。

当前不变量、旧配置升级和备份恢复见 [模型选择架构](../../../docs/architecture/auxiliary-model-selection.md)。
