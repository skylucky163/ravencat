# Chat 功能

单聊消息的 AI 头像表达打开该 AI 个人主页的导航意图，App 将实际消息归属的助手 ID 映射为 `/assistants/[aiId]`；用户头像保持只展示，消息多选期间不执行主页跳转。名称、专属昵称、人设与头像编辑归 Assistants 个人主页所有，对话设置维护回复显示、背景及通话铃声，上下文通过单独入口管理。

个人主页提供模型、上下文与聊天摘要入口，聊天更多顶部的整张 AI 名片可点击进入个人主页，并保留模型、对话、摘要等现有快捷菜单；主页跳转由 App 装配。`AssistantChatSettingsScreen` 按助手 ID 和已有 canonical 会话读取目标，不依赖聊天 Shell 的当前 AI／会话，不创建会话或推进已读；聊天背景使用 `single:<conversationId>`。对话设置的上下文控制区已替换为导航行，与主页打开同一个 `AssistantContextSettingsScreen`。条数、固定起点和历史群聊及其草稿由上下文页独立持有；普通返回回到来源，选择固定起点先保存再由 App 进入目标聊天。模型页由 Assistants 拥有，Host 装配 Chat 的视觉模型选择控件。更多菜单保留原入口，旧设置地址仅重定向；旧 `ChatModelSettingsRouteScreen`、`ChatSettingsRouteScreen` 和 Shell 设置子页面状态已移除。

当前聊天直接消费 `subscribeAIAssistantUpdated` 的提交事实，仅更新身份匹配的助手配置，保留当前会话、菜单、已到达预览和置顶投影。不再依赖设置页给 Shell 回填字段，也不由列表旧快照覆盖新配置；下一轮配置读取和在途执行沿用现有契约。专项验证：`npm run verify:assistant-settings`。

DIY 气泡是 daylight/night 的装饰，只有这两个主题显示入口并应用组合，玻璃、纸条等保持自己的消息表面；没有独立 DIY 主题。外观页只显示「气泡编辑」入口，独立管理页默认展开「我的气泡组合」与「AI 的气泡组合」，两侧可以分别收起。点击名称启用，选中组合的名称、编辑与删除图标统一显示重点色，不额外显示勾选标记；默认项选中时只改变默认文字颜色，并恢复当前侧的主题气泡。`appearance/` 拥有可命名且归属于单侧的气泡组合，不允许跨侧选择或编辑。组合包含 PNG 底图、源像素切线、dp 文字留白、导入时自动确定的显示比例及四槽装饰。正文色属于各自组合，daylight/night 共用一份；外观页编辑当前启用组合的同一字色，切换组合使用其保存的颜色，其他组合不受影响。默认气泡使用主题字色。已保存组合改色即时提交；结构草稿保存保留最新字色，不覆盖另一入口刚写入的值。恢复默认或切换主题不删除组合。`chat_bubble_presets`、`chat_bubble_preset_decorations` 持有 MediaAsset 引用，`chat_bubble_selections` 用复合外键约束组合与侧别一致；清理与备份按真实作品引用枚举，未启用的组合也必须保留。

编辑器通过 Expo Router 的独立 Stack 页面打开，页首左侧编辑预览文本，右侧统一上传／更换底图；预览、拉伸／留白／装饰三个页签和当前参数共用整页滚动容器。预览复用 MessageBubble 的头像、排版与绘制，按普通文字原样显示单字、空格和长文本，也可清空观察最小气泡；长文本在编辑预览中完整显示。预览文字只属于页面状态，不进入组合草稿或触发保存。编辑虚线与装饰手势仅由预览传入。显示比例在导入时按最长边的固定标尺确定，切线调整不改变比例，不暴露比例滑条。四边滑条保持固定刻度，实际上限单独约束切线不能交叉；四边留白独立调整。新底图的拉伸切线四边初始为 0，文字留白与 daylight/night 默认气泡一致：左右 10 dp、上下 8 dp，不随底图尺寸变化。调整切线后可手动使用一键避开边框补足留白，无变化时禁用；留白页签提供当前组合的文字颜色入口。四个装饰槽允许留空，大小表示最大显示尺寸，短气泡按实际宽高等比缩小装饰及相对跟随角的偏移，长气泡恢复至上限；保持图片比例，允许负偏移破形，不撑大气泡；按实际上下溢出量预留消息占位，Token 与相邻消息排在装饰之外，装饰位于自身正文上方。拖动时只更新临时位置，松手后保留落点并自动确定最近的跟随角，中断不提交；短气泡上的拖动换算回最大尺寸下的配置，不把当前气泡尺寸写进组合。测量和自适应由装饰层负责，在 Fabric 的布局阶段同步读取当前节点尺寸，气泡容器在绘制前接收溢出量并预留上下占位；正文增长和列表回收也重新测量。用户消息从乐观发送到正式落库使用同一 clientMessageId 作为列表身份和装饰占位身份，数据库 ID 变化不重建气泡或撤销已有占位，避免原生列表短暂缩高后夹取滚动位置。后续 onLayout 只触发当前尺寸读取，不采用迟到事件中的旧坐标，尺寸和占位未变时不通知列表重排，不生成图片副本；无装饰时不创建测量图层。正式消息的装饰整层 `pointerEvents="none"`，不参与点击、长按和选择。DIY 的 Markdown 不铺独立实底，代码、标号等继承该侧实际正文色。

底图、装饰、切线和留白的修改先留在页面草稿；会话持有缓存副本，退出后释放，迟到的原生准备结果不能修改已退出页面。保存与退出共用 Feature 内的命名 ModalSheet：新组合提供默认名称，已有组合沿用原名，用户可以直接保存或改名后保存；退出时同时提供继续编辑和放弃。路由 usePreventRemove 统一承接返回动作，保存失败保留命名窗口、错误和草稿。确认保存后才通过已有 PreparedMediaAssetBatch 物化媒体，作品、四槽和启用选择在同一 CAS 事务提交。作品 revision 防止旧编辑覆盖，槽位范围及唯一约束在 SQLite 裁决；图片按既有媒体机制去重和引用计数。数据库 155 将 154 的共享收藏拆为两侧独立副本，保留选择、未启用收藏及装饰槽位，文件继续共享媒体身份；更早的单侧皮肤直接保留原归属。数据库 156 为缺少字色的旧组合补足该侧默认值，保留已有组合字色。旧备份按快照版本选择引用表，不访问不存在的新表。会话与页面行为验证：`scripts/verify-bubble-editor-session.mjs`。

消息正文、Markdown、语音、附件和长按沿用现有 MessageBubble；独立图片、贴纸、系统消息和思维过程不套 DIY 外框。`message-bubble-background` 只绘制、让出全部触摸，通过后台共享解码和有界 Bitmap 缓存复用 PNG，按原生 View 的当前边界九宫格绘制，不生成随消息高度变化的位图。图片导入复用公共文件边界，底图与装饰使用各自预算：底图超过绘制预算时等比生成最长边 1024 像素的 PNG 副本；新装饰仅接受不超过 2 MiB 的静态 PNG，字节限制在读取和解码前执行，超过 512 像素的装饰在导入时等比缩小至最长边 512 像素。保留透明通道，不改写原图，小图不重编码。临时副本在持久化成功或失败后清理，保存尺寸与切线均以最终副本为准。已有皮肤与原生绘制仍遵守 8 MiB、边长 3–2048 像素契约，避免导入适配改变旧皮肤的切线坐标；图片不可用时统一报告并显示默认气泡。行为验证：`node --no-warnings scripts/verify-chat-bubble-skins.mjs` 与 `scripts/verify-media-asset-lifecycle.mjs`；原生模块验证：`:message-bubble-background:testDebugUnitTest`。真实设备上的消息菜单、媒体交互和长列表帧耗时仍需安装包含新模块的应用验收。

选图入口由系统文件选择器限定 `image/png`。导入层不因文件内容识别结果与选择器类型标记不同而拒绝，而是在需要时复用 PNG 编码流程产出真实 PNG；满足预算的原生 PNG 沿用原文件。原生绘制层信任导入层的格式契约，只检查文件可读、可解码及绘制预算；损坏与尺寸超限分别报告，不再统一提示重新选择 PNG。

待优化：开发版气泡编辑页滑动有掉帧反馈，后续先在 preview 构建中测量，再确定优化范围。

单聊「更多 → 清除聊天记录」永久删除当前 AI 的全部聊天消息，包括旧版本隐藏的原文、独立展示快照和重写候选；同一事务撤销在途回合与宿主请求资格并清空预览。保留 canonical 会话、置顶、聊天摘要和记忆空间，媒体在 commit 后按剩余引用裁决释放；通话记录仍由 Calls 独立维护，旧通话内容不再进入聊天上下文。清除事实使当前窗口的分页 generation、游标及缓存失效，迟到的旧读取不能恢复已删除的消息。

单聊「更多」与「群聊信息」提供「搜索聊天记录」。关键词按字面包含匹配，英文不区分大小写，按新到旧每页读取 20 条；查询覆盖仍可见的全部持久原文，不受摘要或聊天首屏窗口影响。结果展示发送者、时间、命中高亮和片段，点击后在独立页面按聊天顺序查看附近原文，并继续向前或向后读取。用户搜索沿用消息可见规则，不套用 AI 成员资格，不改变聊天列表位置、摘要进度或消息已读状态。

单聊和群聊按 canonical conversation ID 自动保存未发送的原始文字，页面失焦、切换会话或重启后恢复。草稿独立存于 `chat_text_drafts`，删除会话级联清除；不保存附件、引用或群聊 @ 的成员身份。会话列表通过独立投影显示「[草稿]」与单行摘要，不改消息预览、未读、活动时间或排序。宿主内共享草稿 owner 合并写入，失焦和进入后台排空；异步发送只消费自己捕获的版本，不能清掉之后的新输入。单聊沿用现有发送气泡接管与失败重发，群聊提交失败仅在用户没有继续编辑时恢复文字。

单聊「对话设置 → 流式输出」使用开关，按 AI 独立保存开启／关闭选择。未手动选择时，daylight、night、liquid-glass 默认关闭，moon-kimi、paper-note 默认开启；手动选择跨主题保留。页面与执行宿主从同一角色字段装配本轮配置，在途回复不随修改变化。流式与多气泡可同时开启：当前气泡持续增长，空行或长段达到阈值后的完整句末闭合气泡，随后继续下一泡；不移动已显示的句子。非流式仍在正文完成后分段交付。

单聊和群聊的消息 AI 头像可打开对应个人主页，名称和正文不承担主页导航。群聊复用消息列表已有的发送者身份解析与头像回调，App 将助手资料 ID 映射到主页路由；返回仍回到来源聊天。

Chat 拥有单聊、群聊、消息时间线和回复引擎。外部 Feature 只能从
`@features/chat` 使用稳定公共能力，不得深导入 Chat 内部目录；Host 的运行时装配
才可以使用 `@features/chat/composition`。

应用底栏入口 `BottomTabBar` 按主题选择视觉：Daylight / Night 使用 Rolling Ball，Glass 使用 Melting Ball，Paper Note 使用 Ink Circle。三个变体共用 Tab 数据、触摸入口和未读角标，选择状态与页面导航仍由 App 的 Expo Router 布局持有。Ink Circle 的图标固定，SVG 墨迹在 UI 线程描绘、淡出，结束后不持续运行。

历史上翻在距已加载窗口顶部约三屏时开始预取，每页 15 条，首屏窗口独立维护。原生拖动起点用于建立方向基线，拖动与惯性结束位置也参与同一个分页判定，避免普通滚动回调被合并或暂缓后遗漏用户需求；数据落地和锚点修正不自行续页，保留单请求与最多一个排队需求。

FlashList 的安装补丁由 `scripts/patch-flash-list-scroll-settle.cjs` 维护：预测位移只能占用既有缓冲区，实际视口始终被渲染窗口覆盖；分页与迟到测量按稳定 key 保留阅读锚点，修正后同步更新 JS 窗口。`verify-chat-scroll-settle.mjs` 使用真实列表管理器与 Android 锚点控制器验证快速滑动、迟到布局和暂停期间的末次位置，不在页面叠加第二套滚动补偿。

## 职责

单聊／群聊摘要共用 `summary/` 的 claim、两级交接、编辑、失败处理与查询。总结模型在摘要设置选择，空引用表示单聊当前聊天模型或群管理员；通用配置持续引用，修改后后续调用跟随，失效不替换。群信息页提供一级、二级正文、设置与诊断，群触发条数独立于成员上下文窗口。契约见 [两级摘要](../../../docs/architecture/chat-summary.md)。

四项主客配置实际参与 Host Prompt 装载：单聊带自身主·单聊及已参加群的客·群聊；群聊带自身客·单聊、当前群主·群聊及其他已参加群客·群聊。每群独立额度、客值 0 排除原文与摘要、来源注入开关及输入上界均由现有查询落实。对话设置可一次性复制四项条数到所选／全部 AI，之后独立修改。退出历史及用户注入选择同样由 Chat 拥有，契约见 [主客上下文](../../../docs/prompt/context-window-primary-secondary-design.md)。

群成员管理入口在群信息页的成员网格：虚线加号支持批量邀请，头像菜单提供移除、禁言及解除禁言。用户与 AI 工具共用 `group/application/GroupMembership.ts`。独立「群聊」工具包不限对话场景：所有 AI 可用 `search_groups` 按群名关键词进行字面包含匹配，仅返回真实名称与群 ID（包括未加入群，英文不区分大小写）；`join_group` 申请后直接加入自己，已加入则返回「你已在该群聊」，不重复写入、不解除禁言；`add_group_member` 复用原邀请能力，开放给普通 AI，按目标 Agent ID 与群 ID 邀请，不要求调用者已在该群。退群与改名只操作自己仍参加的群，移除、禁言和解除禁言仍仅主理可对自己仍参加的群使用。独立管理员模型只负责发言规划。成员资格与禁言分开保存；变更事务同时撤销目标 queued/running 任务，commit 后只取消该目标请求，保留已发消息和其他成员任务。规划晚到与动态 @ 在持久调度边界排除不可发言成员；本轮新增或重新加入者从下一轮参与。

发言队列由群提交接缝的实际落库事实和 Runtime 结束原因共同收尾：完整正文为 `completed`，只有思考落库、已发正文被截断／过滤或后续提交／交付失败统一为 `partial`，无正文和思考落库才为 `failed`。长度上限、内容过滤、仅有思考及失败原因保存在任务说明中，队列直接展示，不依赖完整日志；没有明确结束原因时不推断为截断。历史 `failed` 任务若已有可见回复提交标记，界面显示“部分回复”。换代／终止仍由持久 fence 与 CAS 裁决。

退出／被移除在同一事务内保存独立历史快照和系统记录，不调用总结模型；原群后续消息、摘要编辑和改名不更新快照。原群删除后快照仍由 AI 身份持有；重新加入时隐藏旧退出背景，下次退出替换为最新快照。「对话设置 → 历史群聊」只提供查看和注入开关。AI 可通过记忆工具将退出历史交给模型提炼为「【群聊·退出时群名】」记忆，Host 负责跨 Feature 原子组合，转换不擅自关闭历史注入。群内工具产生的系统记录关联发起回合，复用时间线外部条目的排序规则。展示时同一段操作保持一张行动卡，成功提示即时显示在卡片下方、下一条 AI 发言之前；后续过程更新原卡，关闭行动步骤仍保留系统提示。运行状态、历史快照与新列随数据库 141 原子升级，SQLite 完整备份保留记录。验证入口：`node scripts/verify-group-membership.mjs`、`node scripts/verify-group-membership-ui.mjs`。

群成员回复复用 Agent Runtime 与授权工具链。语音、表情意图通过共享 timeline 在当前群任务事务中物化；每条提交检查持久资格，终止后停止执行并丢弃未提交媒体。图片下载／看图／头像／收藏沿用原 owner 和群任务资格；协议、朋友圈、记忆、账本、联网、手机、日程及 MCP 仍执行各自授权和主理限制。视频通话在群中禁止。一起听仅当前主理可用，卡片与后续消息落在目标群，用户操作沿用已有 Activity 网关。

群头像通过 `getGroupAvatarForAssistant` 提供只读查询：普通 AI 仅可读取当前启用的成员关系所在群，主理资格由可信 Host 提供。头像选择与成员关系在同一次查询中裁决，不加载管理员凭据或成员资料；Host 将结果接入应用设置工具和 Media 视觉读取。群聊回复中可省略群 ID 读取当前群，其他场景必须指定。当前群的身份背景提供工具参数 `group_id`，跨会话群背景已有的 `conversationId` 同样可用于定位。

- 管理单聊会话、消息、群聊及其领域模型和仓储端口；
- 摘要模块拥有聊天与通话的统一时间线、逻辑消息计数和原文交接。通话中达到门槛等待挂断，短通话继续累计；一次领取的全部原文在一次调用中整理，成功后原子追加摘要与处理进度。Calls 的只读事实通过 Host 装配到同一数据库快照，不复制通话消息。
- 编排用户消息、外部 assistant 消息、主动回复、时间线查询和群聊命令；
- 由 Chat 自己完成消息提交后的 preview 和交付能力调用；
- 提供 ChatScreen、路由、会话、群聊、消息气泡与输入区；
- `useAgentTransientTimeline` 在合并前统一处理 canonical 与运行片段的到达投影，只确认已到达的 canonical 行，避免 SQLite 读回与原生到达通知交错时气泡消失、重现；各主题共用这份到达资格，切换主题只改变气泡呈现，不提前确认运行片段。交接不依赖滚动或绘制回执。
- 消息事件的全量刷新重读当前已加载身份覆盖的持久窗口，不复用首屏最近 20 条查询。SQLite 在同一读取快照内解析窗口身份，排除乐观发送 ID，保留其余历史并反映真实删除；发送和回复收尾不应通过裁切历史移动列表位置。
- 展开的思维链／行动步骤卡片中，每条思维链正文使用一个 Android 原生文字选区，可跨段落、列点和代码块拖动手柄选取复制。Markdown 保留标题、行内格式和列点，表格以文字分栏显示；工具状态与其他思维链不合并进当前选区。
- 单聊／群聊的原消息菜单在「复制」右侧提供「选择文字」，有可复制正文时启用。独立的主题底部面板持有打开时的原文快照，以一个只读 Text 保留空格、换行和 Markdown 标记，支持跨段选取并使用 Android 的复制／全选工具；聊天气泡、Markdown 排版与原长按手势不变，「复制」仍复制整条消息。面板打开时暂停聊天自动跟随，切换会话或页面失活时关闭。复用既有 ModalSheet 和 TextSelectionScrollView，不增加原生模块。验证：`node --no-warnings scripts/verify-chat-text-selection.mjs`。
- 思维链／行动步骤的展开意图由当前会话列表按稳定身份保存，列表项回收或重建后恢复各自状态；切换或重新进入会话时重置。滚动尺寸仍由每个实例重新测量，收起的行动步骤不投影正文节点。
- 文字选择的焦点不触发聊天列表／卡片滚动，折叠前由原生适配释放选区再卸载正文；输入区只根据真实键盘事件占位，自动转移的焦点不借用历史键盘高度。原生边界见 [原生文字选择](../../../modules/native-text-selection/README.md)。
- FlashList 分页定位修正期间只暂停消费滚动事件，恢复时必须处理末次原生位置；否则手势恰在暂停期间结束时，渲染窗口会停留在旧位置并持续空白。`postinstall` 通过 `scripts/patch-flash-list-scroll-settle.cjs` 修正依赖的事件所有者，保留最新 SyntheticEvent 的生命周期，不重放中间事件、不新增等待计时器。升级列表依赖时审查此补丁；行为验证为 `npm run verify:chat-scroll-settle`。
- 消息列表的持续贴底、触摸暂停和新消息提示统一由 `useChatBottomFollow` 拥有；视口变化与消息布局提交只向它请求跟随。同一帧合并请求，触摸期间保留请求，用户上翻、历史消息定位、切会话及卸载取消请求。FlashList 负责阅读锚定、初始定位和短列表底部排布，不开启自动追尾；分页只读取真实滚动活动。
- 消息下方的用量提示显示 API 返回的总量、输入、输出及缓存命中率（缓存命中 / 输入）；缓存统计随消息 metadata 保存，没有数据的旧消息或服务商显示「未提供」。多气泡仍只在用量尾段展示。对话设置可按角色关闭单聊提示，默认开启，所有主题均使用当前角色保存的选择。
- 通过 conversation、messages、group、reply 各自的运行时端口接收 Host 注入的能力。
- 拥有语音消息的 transcript、播放状态、气泡展示和 T1/T3 原子提交；Speech 只负责 STT/TTS，Media 只负责 canonical 音频资产。
- paper-note 与 moon-kimi 默认单气泡流式，用户的回复方式选择在执行宿主重读配置时同样生效，不依赖页面发送参数。展示合并只处理普通文字；同一模型轮次下的语音、表情等独立消息保留自身元数据。行动步骤与 Token 用量由当前 AI 的对话设置独立控制，所有主题均可显隐；关闭行动步骤同时隐藏思考、工具状态与自主活动过程，保留正文和其他业务系统消息，不修改存档或模型调用。
- 持有普通单聊工具包的持续展开状态，由 AI 主动打开或关闭，与 T3 正式回复同事务提交；Host 负责分包与动态 schema 暴露，状态不代表工具权限。
- Agent 异常终态的错误消息保留错误码、run 编号与模型已返回的工具名／执行结果码，随现有错误气泡持久化，重启后可查看和复制。诊断不保存工具参数、Prompt、正文或 observation，也不把未知结果写成成功或自动重试；取消与 supersede 仍不产生错误气泡。
- 模型请求失败的错误气泡保留客户端已脱敏的接口具体原因，包括模型不支持输入类型、参数、认证或配额错误；不以通用提示覆盖厂商说明，也不要求开启 HTTP 请求诊断才能查看。

单聊对话设置提供上下文跳转行，回复显示、背景与通话铃声保持原分组；流式和多气泡保持原有入口与行为。独立上下文页集中展示按条数注入、固定消息起点与历史群聊。开关采用左侧标题和简短说明、右侧控件的卡片布局；上下文使用「当前单聊、单聊背景、当前群聊、其他群聊背景」呈现四项条数，详细规则集中于标题旁的使用说明。固定起点保留当前状态和用量提醒，历史群聊详情在点击后展示。
名称、人设、头像、上下文可见条数、多气泡回复与群聊管理员配置自动保存；输入草稿校验由页面负责，合法字段独立提交，错误在字段旁显示并保留输入。
通用提交确认复用 shared/ui，聊天及通话背景继续独立更新；当前契约见 [对话展示信息自动保存](../../../docs/architecture/conversation-settings-autosave.md) 与 [模型设置自动保存](../../../docs/architecture/model-settings-autosave.md)。

单聊与群聊的「上传图片」一次最多选择 9 张，每张最多 5 MiB。输入区按选择器返回顺序横向展示草稿，支持逐张移除；重新选择会替换当前附件，取消选择保留原草稿。整批准备完成且没有失败项后才能发送，所有图片与附言复用同一次提交和回复边界，时间线仍逐张显示图片。草稿 owner 持有各自文件，准备途中移除或退出页面也会释放晚到的副本。

## 不负责

- AI Provider、HTTP 与流式传输底座由 `platform/ai` 负责；
- SQLite 连接、schema、migration 与读写调度由 `platform/persistence` 负责；
- Memory、Calls、RavenCat、Wallet 等业务规则归各自 Feature；
- 应用启动、跨 Feature 装配和具体外部能力实现归 `host/composition`。

## 出口与边界

### 普通公共出口

`src/features/chat/index.ts` 是外部 Feature 和 App 使用的唯一普通出口，包含：

- 会话、消息、群聊的公开命令、查询与稳定 DTO；
- AI 消息交付事实的订阅入口；
- `ChatScreen`、`BottomTabBar`、路由屏幕和 Chat router 入口。

当前 `ChatScreen` 由根 `index.ts` 显式导出，App 路由应直接使用
`import { ChatScreen } from '@features/chat'`；`presentation/shell/ChatScreen.tsx` 是实现路径，
不是跨 Feature 的深导入契约。

普通出口不暴露 `configure*`、`publish*`、`ProcessAIReply`、turn/projector、具体
repository 或 SQLite adapter。外部 Feature 不得自行拼接 persistence、session preview、
UI 刷新和事件发布，应调用完整的 Chat command（例如
`appendExternalAssistantMessage(s)`、`requestProactiveChatReply`）。

### Host-only composition

`src/features/chat/composition.ts` 仅供 Host 组合使用。它负责注入 Chat runtime、配置
delivery handler，提供执行宿主所需的内部入口，并暴露 Chat 自己的具体
SQLite repository 以便 Host 装配。这里的配置函数、执行入口和 repository/adapter 不是
普通公共接口，其他 Feature 不得依赖。

业务 SQL 仍位于 Chat 的 `infrastructure/` adapter；运行时 SQLite 读写必须经过
`@platform/persistence` 的 `databaseCoordinator`。

### 单聊语音消息

用户语音先在事务外录制并由 Speech 取得稳定转写，结束录音后返回待校对 draft；此时没有 canonical 消息，不更新预览，也不触发 AI。用户确认最终转写后，才通过 Media prepared batch 与 canonical 用户消息在 T1 同事务提交。draft 持有临时录音文件；取消释放文件，发送失败保留可重试草稿，成功提交或 discard 后进入终态。AI 的 `send_voice_message` 在单聊与群聊按既有授权暴露；TTS 与 backing prepare 在事务外完成，语音 intent 按 run-local sequence 在单聊 T3 或群任务提交事务内物化为 MediaAsset 与 assistant 消息。

语音正文是模型可见的 canonical transcript，但气泡、会话预览、通知和交付回调默认只显示 `[语音消息]`。`voice_played_at` 只在普通媒体播放器确认 started 后幂等写入，不能复用消息已读状态。

历史 AI 语音在模型上下文中保留实际转写正文，语音来源事实随原文投影传递；每条转写前由 Prompt 组装器独立附加 system 提示，说明它是历史语音转写、发送语音仍须实际调用 `send_voice_message`，不能将转写标签或发送要求拼进 assistant 正文成为可模仿的回复格式。该提示不受消息时间戳开关影响，也不写入持久消息。普通聊天正文不会自动合成语音；schema 尚未暴露时先展开 `chat` 工具包，工具说明负责调用步骤与失败语义。

`send_voice_message`、`send_image` 与 `select_sticker` 必须传入 `on_success`：回复已完整时选择 `finish`，还有语音、图片、表情包、文字或其他操作时选择 `continue`。图片和表情在工具完成后由回合提交 owner 经原 fence 提交并交付，`continue` 不再扣留媒体；T3 绑定同一消息的最终顺序，不重复发送。语音和重写媒体仍随整轮提交。整批工具成功且最后一个工具选择 `finish` 后，Runtime 直接结束，无需模型补充“已发送”或空正文。任何工具失败仍回灌模型，失败召回不自动重试；同批前面的 `finish` 不会截断后面的工具。

### 会话列表与预热

单聊与群聊共用 `shared/utils/conversationListOrdering.ts`：置顶区优先，区内按真实可见消息活动时间与 `pinnedAt` 的较晚值倒序；普通区只认真实可见消息活动，无消息时回到创建时间，最后按创建时间与 ID 稳定排序。置顶写独立 `pinned_at`，取消置顶同时清空；打开会话不改变活动时间，清历史或删空后的旧消息不继续影响排序。

列表和 `presentation/shell/conversationPreloadCandidates.ts` 共用同一排序。已有会话立即进入页面，timeline cache 命中、缺失或预热失败只影响消息加载，不构成导航门槛。预热不创建单聊身份；热点集合随候选身份/顺序变化重算，消息事实变化（包括时间回退或清空）定向失效并重读；缓存遵循 LRU，不以打开页面制造列表活动事实。

## 运行链路

```text
presentation / @features/chat command
  -> conversation、messages、group、reply 各子域 application
  -> domain port
  -> Chat infrastructure（SQLite 经 databaseCoordinator）
     或 Host 注入的 AI / tool / call / delivery 能力
```

普通用户回复主链为：

```text
sendUserMessage
  -> canonical user commit
  -> Android execution host
  -> executeUserReplyTurn
  -> ProcessAIReply
  -> ChatAgentReplyFlow
  -> AgentRuntime
  -> AssistantTurnCommit
  -> assistant delivery
```

消息成功提交后，Chat 更新自身 UI 并交付 assistant 消息；Memory 不再通过逐消息事件摄取。

普通回复整批提交后，`reply/delivery/AssistantMessageArrival` 承接宿主注入的原生
到达进度。Tab/会话红点、实时列表预览和非流式多气泡时间线共享这一展示投影；
原始消息与持久预览仍保持完整提交。原生接口变更需要更新设备开发包，Metro 重载不能替代。

## 常见排查入口

### 消息收藏

单聊和群聊长按已发送的用户／AI 消息可收藏当前单条气泡，不展开 AI 整轮回复。所有主题保留长按入口，Moon Kimi 的内联操作继续展示；文件卡与语音卡由自己的触控入口打开同一菜单。表情包不提供翻译；通话状态与通话来源文本不提供翻译、引用和收藏；过程记录、业务卡片、分享记录和生成中的消息不参与收藏。

「我 → 个人」下方的「收藏」进入独立页面，提供全部、文本、音频、图片、txt/md 分类，按收藏时间倒序并使用稳定游标分页。图文与文件配文保存完整快照，按附件分类；表情包转换为普通图片展示，语音保留音频和转写，详情可查看完整正文、图片、文件并取消收藏。

`favorites/` 拥有快照、Repository port、命令与 SQLite adapter；Host 注入收藏仓储，App 持有具体路由。收藏不对消息、会话或角色建立级联外键，原文后续改写或删除不影响快照。消息菜单每次打开读取当前收藏状态，已收藏显示实心星标与「已收藏」，再次点击取消收藏；状态读取和写入期间禁止重复操作。重复收藏命令保留同一条及原收藏时间；收藏与消息删除在数据库事务内裁决。旧附件在事务外使用现有 Media prepared batch 准备，最终资产与收藏同事务提交。收藏引用进入 Media 的枚举、回收与备份清单，取消收藏提交后才裁决释放候选。收藏语音复用聊天播放器，以独立身份播放，不再更新原消息的已播放状态。

新上传文档仅支持 TXT/MD；正文最多 6000 个 Unicode 字符，超限明确拒绝，不再静默截断，预览摘要仍独立截短。旧 CSV/JSON 的查看与资产迁移保留，不与新上传资格共用白名单。验证入口：`npm run verify:chat-favorites`。

### 其他消息操作

单聊与群聊引用保存当时的发送者界面名称、正文、附件、语音转写、表情包和朋友圈快照。发送前预览与已发送引用显示发送者名称，私有备注只供界面使用，不进入模型或摘要。引用区可预览图片、打开文件和播放音频；朋友圈引用复用分享卡片，展示原帖作者、正文及图片缩略图，点击打开原帖，发送者与原帖作者分别表达。引用语音使用独立播放身份，不改写原消息的已播放状态。媒体引用随消息 metadata 进入现有资产枚举与回收，原消息删除或改写不影响已发送快照。模型侧只提供被引用媒体的类型、名称和 `mediaAssetId`，由 AI 关联历史上下文，不因引用再次读取图片或发送文件正文、音频内容。旧引用缺少发送者名称时不补造身份；仅有 `reply_to_text` 时继续显示已有文本。

单聊和群聊的消息长按菜单支持复制正文、手动改写、删除、引用和翻译。所有操作保留固定槽位，不可用项置灰禁用，语音转文字也不临时插入；全部操作均不可用时不显示菜单。改写适用于已发送的普通文字与混合消息正文，保留发言者、附件和消息身份；语音、纯图片、表情包与状态卡不支持改写。改写正文和当前预览在同一事务提交，不改变会话活动时间，也不自动触发 AI 回复；编辑期间正文变化或消息删除时保留草稿并提示。

单聊「重写」只面向普通用户输入产生的最新已完成回复回合，后续存在新用户消息或当前正在回复时不提供入口；用户消息、群聊、主动消息及通话等旁路回复不支持。点击任一文字、语音或表情气泡，暂时隐藏整轮 canonical 回复、思考和工具记录，顶部显示「对方输入中」。页面只提交持久化重写意图，原 Android execution host 使用当前模型配置、原回合的全部现存用户输入和附件执行既有 Agent 流程。直接历史截到原输入，旧回复及旧工具记录不提供给新请求；已有摘要保留原样，允许含工具的回合重写和重复执行，已经发生的业务事实不撤销。

重写复用同一个回合 owner 与 T3 fence，回复游标不回退；成功时新消息、旧回复候选存档、旧 canonical 条目删除和预览在同一事务交接。生成失败、空回复、取消或重写孤儿恢复均保留旧消息，不新增「已重写」标记。新用户输入、手动编辑、删除和清历史撤销重写资格，迟到结果不能提交；旧语音等媒体候选仅在成功提交后交给 Media 裁决。验证入口：`npm run verify:chat-regeneration`。单条与多选分享均已接通。

重写前显示说明，可勾选「不再提示」并在确认时保存本机偏好。AI 消息菜单的「历史版本」紧邻「重写」，按整轮保存候选，包含正文、思考、工具状态和媒体；手动改写只修改当前采用版本，不新增候选。最新一轮且无执行／展示中的回复可以显式采用旧候选，浏览本身不切换；采用在 Chat 事务中替换唯一 canonical 回复，沿用当前回合 owner、输入区间和活动时间，不执行模型、工具或消息通知。后续用户输入或另一轮 AI 消息提交后永久锁定旧候选，即使删除后续消息也不解锁。旧版本继续可查看、复制和预览媒体，不进入普通消息、上下文、摘要或未读查询。已有摘要、记忆、关系和工具业务事实不回滚。删除当前轮任一消息同时删除该轮候选；清历史删除全部原文、展示快照和候选，删除会话级联删除候选。历史媒体接入 Media 引用枚举、释放裁决、备份和会话删除候选。

单聊和群聊「多选」从长按菜单进入并选中起始消息，顶部显示「已选 N / 20 条」与取消，底部以删除和分享替换输入栏。输入草稿、附件和引用保留；Android 返回键先退出多选，失焦或切换会话清空选择。用户消息逐条计数，AI 按同一 run 的完整回复计一条，连续工具步骤、思考与正文联动选择；无 run 的现存历史按已有 logicalMessageId 归并，不猜测相邻消息归属。仅已发送的用户／AI 普通消息与媒体消息可作为选择入口，生成中的临时条目与独立业务卡片不参与选择。选择同轮任意气泡切换整轮状态，每轮只在第一个可见条目显示勾选控件；新消息不自动选择，多选期间不自动滚到底部。

单条长按「分享」与多选底栏「分享」共用目标选择、完整预览、可选附言与确认发送。一次发给一个其他 AI 单聊或群聊，最多 20 个选择单位；单条 AI 分享仍展开完整回复轮次。取消保留来源页选择及草稿，成功才退出多选；发送中禁止重复点击，失败保留预览。分享创建一条用户记录消息 `kind=shared_record`，非空附言在其后作为独立普通用户消息显示；两条及媒体引用沿用同一次单聊 canonical 提交／群用户消息与 plan 换代事务，以尾消息为输入上界，只启动一次回复。commit 后单聊宿主启动失败仍提示「记录已分享」，不把已提交消息当作失败重新发送；群聊继续沿用跨页面自动召唤。玻璃主题的记录卡沿用外层气泡，不额外叠加底色；Android 分享弹窗使用底部留白避让键盘，输入法收起后解除附言框焦点，避免透明系统栏下窗口未缩放或高度反馈导致闪动。

`SharedChatRecord` 保存原作者类别、姓名快照、稳定 agentId、时间、可见正文、附件和表情快照。整轮工具只保留可见历史状态，省略原始工具输入／结果与私有思考；语音保留转写。再次分享保留内部原作者，原消息改写或删除不改变快照；资产引用位于记录内部，仍由 Media 的 JSON 引用枚举裁决释放，旧 URI 在已有附件准备／发送事务中归入资产。

聊天记录与时刻共用 `useChatContentShare` 的目标选择、提交身份、附言和失败状态，界面使用 `@shared/ui` 的 `ShareSheet`。公共窗口只接受目标展示数据、预览插槽和交互回调；目标目录与单聊／群聊提交仍归 Chat。以后增加分享内容时沿用此流程，内容快照和卡片保持各自的契约。

时刻卡片持久化为 `kind=shared_moment`，保存正文与图片的发送时快照；原作者和聊天发送者分开表达。模型使用公开名称，并在当前输入、历史及摘要中按接收者 agentId 生成身份语义；卡片点击通过 Host 打开最新原帖。再次分享包含该卡片的聊天记录时保留内层时刻快照及图片引用。AI 的 `share_moment` 只准备卡片意图，由现有回合时间线在提交 fence 内保存，不另行写消息。

模型始终把分享当作用户提供的历史资料；每个接收者按自己的 agentId 生成「自己」，不按姓名猜测，也不把标记存进快照。当前输入、私聊未总结原文、群聊历史和管理员规划读取完整记录；摘要任务带 currentAgentId，要求保留重要发言的来源与原作者，避免把其他 AI 发言记成自己的。分享图片复用接收角色自己的视觉链路，并保留对应记录条目与原作者；历史读取不重复识别图片。验证入口：`npm run verify:chat-message-share`。

选择状态由共享 presentation hook 持有，删除用例在单次 databaseCoordinator 事务内按锚点读取完整轮次，不受历史分页和主题气泡合并影响；全部正文、思考和工具过程记录、单聊／群聊预览及重写资格撤销一起提交。独立业务卡片和工具已产生的业务事实不随聊天轮次撤销。commit 后发布 `messagesDeleted`，统一时间线订阅按实际删除 ID 移除条目，保留已加载历史、分页边界与阅读位置；删除前发出的同步查询也不得复活这些 ID。统计、固定上下文与悬浮预览消费同一删除事实重读自己的投影。执行宿主通知与媒体候选释放留在 commit 后，失败保留选择。单条菜单删除保持原有逐气泡语义。验证入口：`npm run verify:chat-message-selection`、`node scripts/verify-chat-message-commit.mjs`。

## 聊天原文搜索与摘要

`messages/aiTools/SearchChatMessagesTool.ts` 提供 `search_chat_messages`，通过消息应用查询和 MessageRepository 在同一数据库快照内完成 AI 身份授权与原文检索。工具位于记忆工具包，默认查询当前会话，也可指定自己的单聊或仍参加的群；关键词按任一词字面匹配，支持时间范围与每页 20 条分页。结果带消息 ID、公开说话者、原文和时间，结构化 @ 使用公开名称。已被摘要的原文仍可查；删除、清除前历史、未交付消息、思维链和工具过程不返回。查询不改变摘要进度，不读取通话转写或媒体文件，不把关键词未命中解释为从未发生。行为验证：`npm run verify:chat-message-search`。

`read_chat_message_context` 使用搜索返回的消息 ID 定位语境，保留搜索中的完整正文。它沿当前 canonical 时间线返回锚点及前后消息气泡，按旧到新排列；`before`／`after` 分别默认 3、范围 0～10，结果的 `hasMoreBefore`／`hasMoreAfter` 提示是否可从边缘消息 ID 继续读取。锚点授权、相邻查询和公开名称投影共享事务快照，邻居沿同一会话读取，不重复裁决已确认的访问权限。不查询未采用的重写快照；采用版本切换、删除或清除使旧锚点失效时，明确返回不可读取，不能改读别的消息。搜索与附近上下文复用同一可见范围和正文投影，验证沿用上述入口。

聊天「更多」通过「相遇痕迹」菜单入口打开独立 Expo Router 页面（`chat/[aiId]/statistics`），与其他单聊管理功能共用原生 Stack；标题返回、安卓系统手势和返回键由同一路由栈处理，退出后回到「更多」，不另加页面级 BackHandler。页面直接聚合当前 AI 单聊中仍保存的已发送消息，不从摘要恢复统计，不受历史分页影响；清除聊天记录或删除消息后，对应原文不再计入。用户消息逐条计数，AI 按完整 run 归并，没有 run 的历史分段按逻辑消息 ID 归并。字数只计用户／AI 正文 Unicode 字符（含标点和空白），语音计转写，思考、工具状态、业务状态卡和通话正文不计入。Token 从原始消息已保存的聊天调用用量聚合，同一调用的前言与工具状态去重，保留 Agent 循环用量；不额外累计摘要生成调用，缺失用量不估算。相遇时间直接使用 Assistants owner 已提供的 AIProfile.createdAt：AI 建表以来创建时间一直必填，创建时写入、更新设置不改写，备份恢复保留原值。聊天层信任该契约，不再查询首条消息、重复读取创建时间或增加旧数据兜底。天数为已度过的完整 24 小时，起始时间按设备本地时区显示到分钟。

聊天「更多」通过宿主导航打开独立摘要路由；摘要列表与新增／编辑均由 Expo Router Stack 承载，不再由菜单或列表持有页面弹窗。摘要正文与列表布局仍归 Chat presentation 所有。

summary/ 拥有一级、二级永久摘要、开关、token 归纳阈值与查询工具。菜单“聊天摘要”提供两级查看、编辑、删除和清空；两级独立维护，不因另一层编辑或删除自动更新。单聊·主决定近期原文保留量，一级只领取该窗口之前的整批原文，批次默认跟随单聊·主，也可单独固定；两者均为 30 时，累积到 60 条才总结较早 30 条，保留较新 30 条。总结期间保留全部未处理原文，成功后才交接，摘要与对应原文不重复注入；一级达到 token 阈值时领取当时全部待归纳摘要，含刚新增的一批，成功提交二级正文和来源标记后才替换上下文。ChatTimelineSql.ts 与持久 run 锚点保持原文交接顺序，不保存原文副本。

生成开启时 Host 读取剩余原文；暂停且无固定时绕过摘要游标读取最近 N 条逻辑消息。已有摘要是否注入独立控制。对话设置可返回消息列表，由长按菜单固定具体消息起点；固定范围包含起点到最新全部原文，暂停两级生成但保留原游标与近期参数，页面显示当前起点与逻辑对话数。取消、删除或清空起点后恢复近期窗口，生成需手动开启并沿原进度续接。全部设置按 AI 的 canonical 单聊保存，不跨 AI 生效。Current Input 单独保护。search_chat_summaries 由 Chat 拥有并放入记忆工具包，按时间与关键词查询，两级和已归纳原记录均可查，删除正文立即退出后续检索。稳定命令／查询在根出口，模型 port、具体 Repository 和 worker 装配在 composition.ts。当前契约见[对话两级摘要](../../../docs/architecture/chat-summary.md)。

回复错误（`kind=error`）与已落库的工具终态（`type=toolStatus`）也是模型可见的历史资料。所有工具统一保留调用记录，包括通话、语音发送和表情包查询／发送；媒体消息与通话卡片不替代工具历史。工具意图提出时建立批次状态，参数或授权拒绝也保留失败状态。通话提交后停止模型续轮，已经完成的工具记录仍通过 canonical 提交进入后续上下文。
自主唤醒复用普通单聊 Prompt 和完整摘要／未总结原文，只在末尾追加明确来源的唤醒输入。Chat 先保存开始记录，再准备并执行 Agent；流式思考和行动状态持续更新同一稳定条目，收到模型输出即记录响应证据，`type=agentActivity` 进入同一上下文。失败／取消保留半段原文，启动／回前台只将旧进程记录结算为中断，不重跑。响应证据不代表工具成功。过程记录不改写预览、未读或通知；真实语音／贴纸消息的媒体保存和消息引用同事务提交，随后沿用统一交付。

摘要游标不能越过仍在增长的条目，也不能越过尚无终态的自主 run；等待模型或工具时即使没有流式行，也必须保留整个 run 的原文，避免后续追加内容落到摘要游标之前。
`buildChatSystemEventModelText` 将它们标注为应用事件，以无指令权限的 `user` 上下文按 canonical 顺序传入，
不把 Chat 的 `senderType=system` 映射成 API 的高权限 `system`。摘要 N 按逻辑对话消息计数，同一 `logicalMessageId` 的分段合计一条，新发送的单聊整组图文共享该身份；范围内的应用事件
随同摘要与游标一起交接。工具记录复用消息 metadata 中已保存的 `toolExecutions`，把调用 ID、名称、参数、逐次状态和文本结果一并作为无指令权限的历史资料交给后续模型与摘要；不把旧记录重建为待执行调用或孤立的 API `tool` 消息，不回放工具附图。旧记录没有具体结果时不补造结果；`proposed` 不代表已执行，`running` 的结果未知，批次成功或失败也不能代替逐次结果。摘要正文仍由模型生成，不保证完整保留每个媒体 ID，长期找回下载素材使用 Media 查询工具。
已撤销的消息与其他无模型语义的展示条目不进入上下文；运行中或中断的工具记录只表达当时已记录的状态，不推断成功。同一 run 内仍由 Agent Runtime 回传真实工具调用与结果。

普通聊天与通话默认复用所属 AI 的真实人设以理解身份与词义，任务明确为重要记忆提取：筛选概念、实体、重要事件、约定，以记忆对象为主语逐条写事实、含义与状态，按关联组织，不按日期回顾聊天；群聊沿用同一规则并保持中立身份。二级从一级正文重新提炼与合并记忆，不沿用日期纪要。无重要信息的话题直接略过，无新增时只返回固定句“本批无新增。”。一级、二级均只返回纯正文，不要求 JSON 输出包装；模型请求边界负责非空与截断检查，并将整句无新增信号转换为 `null`。成功空结果只推进处理进度与完成任务，不保存摘要正文、不注入上下文、不反复请求；二级仍消费来源归纳标记，保留原记录供用户管理。提示词要求每段一级正文控制在 500 个 Unicode 字符以内、写得更短更好；实际不以字数拒绝有效正文，不截断或重复请求。两级真正失败后最多自动重试一次，旧任务已用完预算时在队列准备阶段暂停；手动重试单独执行一次。

两级任务正文可在「提示词中心 → 按需提示 → 其他提示词」分别编辑、恢复默认或将草稿全局应用到现有 AI；群聊一级、二级是独立条目，只保存全局正文。提示词启用状态直接派生自 Chat 的自动生成／二级设置，不另设开关；已有摘要注入开关不控制生成，固定起点时两级停用。Host 按来源 AI 读取单聊正文覆盖，辅助模型沿用同一配置；群摘要读取自己的全局正文并保持中立身份，不借用任何成员的覆盖。正文修改从后续请求生效，不重写已有摘要，也不改 Chat 处理进度。配置与页面所有权见 [Prompting](../prompting/README.md)。

普通聊天与通话按统一时间线共同累计 N；通话中达标等待挂断，短通话继续累计。Calls 经 Host 端口提供仍可见的完整文本及接通／结束时间、类型、时长；这些事实仅作为本次总结输入，Chat 不为摘要段保存通话关联或事实副本。Chat 复用同一前台队列、模型请求和持久 claim；一次调用完成后一起交接。单聊的 N 默认跟随该 AI 的单聊主视角条数，摘要设置中可手动固定为其他值。

处理进度与摘要正文分开持久化：普通消息使用 canonical cursor，通话使用会话级已处理 ID，两者均不绑定摘要段。提交正文与推进处理进度同事务完成；提交前保留待总结原文，提交后注入摘要正文与讨论时间。用户删段不复活原文或重新总结，清消息与删除源通话不删除已有摘要。清空摘要使旧 claim 失效并建立通话时间边界；跨边界的进行中通话只总结此后仍保留的文本，不复制来源正文。未接／拒接不生成交谈摘要。旧摘要通话关联表在启动升级中退休，已有正文与处理进度保持不变。

## 图片消息展示与发送

AI 的 `send_image` 位于图片工具包，单聊、群成员回复与自主执行沿用当前授权。网络图片先用 Media 的 `download_image` 保存，再使用 `media_asset_id` 发送；也可复用历史消息或下载查询中的图片 ID。每次调用形成一个已有 MediaAsset 的图片 intent，按工具顺序交给原有 timeline 与回合 fence 提交，不复制下载、文件或消息保存流程。消息保存为普通 `kind=image` 附件，直接复用用户图片的展示、原图预览、引用、分享和媒体引用回收。取消或失去提交资格时丢弃未提交 intent，已下载素材仍归下载记录持有。

新用户图片与文件附件在事务外准备 MediaAsset batch，在原消息提交事务内物化稳定引用。提交失败补偿 canonical 准备文件；群聊保留当前输入草稿，单聊失败乐观气泡独立持有源文件供重发。成功后释放草稿源；取消、替换、失败气泡移除和页面退出都撤销各自持有，最后一个真实消费者退出后才删除文件。历史 committed legacy 文件不登记为草稿，不由此回收。用户/AI/群头像新写入也已切换稳定资产，确认头像后展示最终 URI 并回收 picker 副本。

一次发送中的每张普通图片独立保存为无气泡图片消息，文字（以及文件附件）保存在尾消息。单聊在同一个 T1 事务内提交整批消息、换代一次，commit 后只通知一次回复宿主；模型按原有固定输入区间同时读取这些独立消息。群聊同样在一次事务中提交完整批次，以尾消息作为计划换代和自动召唤的输入上界。引用和群聊结构化 @ 属于尾消息，乐观时间线与持久提交共享拆分及消息身份规则。

昵称仅属于用户界面。新引用和分享条目在生成快照时，按结构化 @ 的稳定目标 ID 生成独立 `modelText`，公开名称目录只取助手 `name`；界面正文 `text` 保留原称呼。模型的引用、分享记录和摘要共用这份公开正文，再次转发保留它，不重新从界面文字猜身份。分享来源标题 `sourceName` 只用于卡片和预览，不进入模型；作者标识继续使用公开名称与稳定 agentId。用户普通正文不通过昵称字典替换。`verify:chat-message-share` 验证跨 AI 分享、群昵称引用、再次转发和摘要输入的隔离。
旧引用或分享没有保存公开投影、且正文含 `@` 时，模型只收到身份信息缺失的占位说明；界面原文不变。旧快照丢失了结构化提及目标，不能按当前备注猜身份，也不能把原文当成已经公开化的内部数据。

普通图片点击后全屏显示原图，支持双指缩放、双击放大／还原与放大后拖动；单指轻点退出，双击优先，双指触摸与已激活的拖动不会触发点击退出。关闭后销毁预览状态。表情包保持独立 Sticker 语义，只展示卡片，不提供点击预览。历史已提交的混合消息不做拆分迁移。

历史图片解析中显示加载状态，只有主图与缩略图均不可用时才显示“图片不可用”；各状态保持相同图片尺寸。当前会话列表分别保留最近使用的图片、表情包和分享卡片资产的成功解析地址，每类最多 200 项；普通图片按完整媒体引用隔离，朋友圈分享卡片的头像和图片按媒体 ID 复用地址，滚动回收或卡片重新挂载时不重新转圈。缓存只存 URI，不持有文件或位图，失败不缓存，原生图片加载失败时移除对应分享资产地址，切换会话列表或卸载时释放。大图预览仍按消息身份重置；识别 metadata 的变化不重启图片加载。MediaAsset 的文件存在性由 resolver 保证，展示层只检查历史裸 URI，不重复校验资产或计算内容 Hash。回归验证：`npm run verify:chat-image-loading`、`npm run verify:chat-message-share`。

## 图片识别模型选择

Chat 的 `chat_assistant_image_settings` 按角色保存视觉识别模型 ID，当前角色模型设置提供唯一选择入口。未选择时原图直接交给聊天模型；选择后先识别，再提供文字转述。聊天附件（包括群聊按目标角色组装的图片）、主动消息图片与通话摄像头截帧共用同一解析；已选择模型失效或识别失败时不自动改为直传。朋友圈和表情包系统保留各自的视觉选择。

聊天图片附件确认走直传路线后，由附件输入组装层读取提示词中心的 `input.image_grounding`，开启时追加独立文字片段，关闭时完全省略。正文不写回消息，也不进入展示文本；OCR 路线已有识别结果或失败说明，不再追加提醒。通话快照与图片工具仍使用各自的观察说明，不消费附件提醒。

群成员各自进行视觉处理，允许不同角色对同一张图片形成不同理解，不改为全群共享一次分析。文件读取继续保留 6000 字符和 CSV 前 12 行，分页工具与完整文件读取待产品决策。相册/拍照与文件选择器现有大小限制保留；暂不增加相册保存或外部文件分享入口。
模型资产仍由辅助模型中心持有，Host 装配 `ChatImageModels` 的窄端口；详见 [模型选择架构](../../../docs/architecture/auxiliary-model-selection.md)。

摘要任务、失败重试与调用诊断由 summary/ 持久保存，一级／二级独立计数、共用 claim。主列表只有一个二级集中编辑入口，一级只显示未归纳记录；二级页用一个正文框编辑，已归纳来源跨批次按时间排列，展开可编辑，调用信息仍保留。合并正文和来源关联同事务提交，拒绝覆盖编辑期间的新二级；失败详情仍可静默排队重试。页面共享主题表面并适配原生玻璃。摘要设置独立路由保存阈值、等待时间与输出额度，输入自动保存，离开先确认草稿。详见[任务与页面契约](../../../docs/architecture/chat-summary.md)。
