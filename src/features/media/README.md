# 媒体与 AI 图片工具

MediaAsset 是图片身份及持久文件生命周期的唯一 owner。业务记录保存媒体 ID，文件放在应用内部 `persistent-media/catalog/`，引用、共享去重、备份和回收沿用同一 catalog。

## AI 图片链路

文生图采用两条独立落盘链路，只共享辅助模型资产和 Platform 的供应商图片客户端：

生图资产创建时选择硅基流动、MiniMax、豆包 Seedream、阿里千问、OpenAI GPT Image 或可灵 AI，保存后供应商固定，仍可修改本供应商下的模型、Key 和参数。供应商决定固定官方地址和已适配模型列表；只有新建阶段切换供应商会清空旧 Key 与服务绑定。执行与 UI 在读取配置时确认供应商、地址和模型匹配。

硅基流动共接入六款模型，由完整模型 ID 决定能力和请求字段，统一走原生 JSON `/images/generations` 与 `images[].url`，不走 OpenAI multipart edits 或流式预览：

| 模型 | 参数与参考图契约 |
| --- | --- |
| `Tongyi-MAI/Z-Image`、`Tongyi-MAI/Z-Image-Turbo` | 仅文字生图；约百万像素比例档位，默认 1024×1024，3:4 为 864×1152 |
| `Qwen/Qwen-Image` | 仅文字生图；按厂商推荐尺寸映射比例，默认 1328×1328，使用推荐 50 步与 CFG 4 |
| `Qwen/Qwen-Image-Edit`、`Qwen/Qwen-Image-Edit-2509` | 必须提供一张参考图；不支持指定比例，不发送 `image_size` |
| `Kwai-Kolors/Kolors` | 可选参考图；提供 1:1、3:4、9:16，3:4 为 960×1280 |

这些模型不提供未适配的画质、格式、压缩或自定义清晰度选项。比例选项显示实际像素，画布按请求尺寸或参考图比例预留，成图仍以真实检查尺寸为准。提示词原样发送，其中的比例文字不改写尺寸字段。切换模型清空本次参数；切到不支持参考图的模型时，清理缓存或等待在途请求结束后清理，过期选图不能重新进入请求。

阿里百炼千问采用原生 DashScope 同步生图协议，文生图和参考图共用一次请求。Platform 在已有百炼服务域名下选择原生路径并映射输入、尺寸和图片响应，用户不需要修改已有连接或模型选择；不自动改走兼容接口或重试。

可灵 AI 使用国内开放平台的 API Key，接入 Kling Image 4.0 的单图模式。文生图与可选的一张参考图共用接口，支持模型默认比例、固定比例与 2K／4K 清晰度。提交一次后在同一请求生命周期内查询任务，取消只停止本地等待，远端任务可能继续运行。

在辅助模型中心创建「自定义 · OpenAI Images 兼容」资产，可从「选择已有服务」导入 API 地址和 Key，也可手动填写 API 基础地址（例如 `https://api.example.com/v1`）和 Key。填好模型 ID 后，到「AI 生图」显式选择该资产。生成默认使用服务参数。用户可以选择图片比例、画质和文件格式并逐项检测，每次只提交所选参数并请求一张图。比例按成图实际宽高核验，检测结果同时显示实际像素。检测图只用于核验并随即清理。检测状态留在页面，切换模型或连接会清空状态。字段被明确拒绝时恢复服务默认，取值被明确拒绝时可改选其他值。AI 工具使用服务默认参数。

硅基流动的官方地址使用「硅基流动」提供方，按模型提供适配过的比例与尺寸。填入自定义配置时会在发起请求前提示改用该提供方。其他自定义接口返回 HTTP 400／422 时显示脱敏后的具体原因，只有明确拒绝当前参数或取值才将检测结果标红。

参考图选择与 AI 媒体解析交付 Device 已检查的格式、尺寸、字节数。进入生图前只按供应商契约检查上传限制：MiniMax 的 JPEG／PNG 与小于 10 MB、千问的 10 MB／单边 8000／长短边 10:1、Seedream 的 30 MB／总像素 3600 万／每边大于 14／长短边 16:1、GPT Image 的小于 50 MB、可灵的 JPEG／PNG 与 30 MB／每边至少 300／长短边 5:2；不满足时在读取 Base64 和计费请求前明确失败。文件真实性不在供应商层重新解码检查。

生图页的比例、清晰度、渲染画质、格式与压缩质量属于本次请求，不写入模型资产或全局选择。参数按对应协议能力展示；MiniMax `image-01-live` 没有自定义尺寸，Seedream 5.0 Flash 只有 1K／1.5K／2K，4.5 为 2K／4K。人物参考使用一张相册缓存图片，更换、移除或离开后清理；参考图只作为本次外部服务输入，不登记 MediaAsset、不写相册。AI 工具与页面共用同一能力表：Host 在每次运行准备时读取当前选择，只暴露该模型支持的比例、清晰度、渲染画质、格式、压缩质量与参考媒体 ID；枚举与页面选项一致，提示词上限随模型收窄，编辑模型将参考图标为必填。不支持的字段不进入 schema，由既有 Runtime 参数边界拒绝，不通过试调用发现能力。模型未配置或失效时只保留基础参数并说明不可用，不影响其他工具的准备。素材文件及生成事实仍沿原有引用链路处理。

页面始终保留对应比例的画布，所有供应商统一在画布中央显示本次已等待秒数与真实阶段，阶段或中间预览更新不重置计时。生成期间整块画布显示改编自 MIT 许可 img-fx Chromium Flow 的像素场，取代原有曲线、扫光和计时卡片。动效复用已安装的 WebView，以纯本地 WebGL 分两遍绘制：小纹理只计算每格颜色，画布采样纹理组成方格；帧率限制为 24 FPS，渲染像素比限制为 1.5，减少动态效果时只绘制静态帧。原图仍由 RN Image 展示，加载完成后像素遮罩溶解并释放 WebView；取消或失败立即移除动效，新请求重新拥有自己的绘制实例，不让上一张图的溶解结束新请求。动效文档不接收图片、提示词或凭据，以 CSP 禁止网络资源并限制导航，不驱动请求、计时或持久化。来源与完整许可见[参考实现来源](../../../docs/third-party/reference-implementations.md)。这些 UI 动画不表达服务端完成百分比。GPT Image 通过 `expo/fetch` 接收最多两张中间预览，只有最终事件才可继续落盘；预览不写文件或业务表。MiniMax／Seedream／千问沿同步请求显示阶段，不把逐图完成事件当成绘制预览。按钮只显示「生成」「取消」或「重试保存」，成图状态显示实际尺寸、文件体积与相册保存结果。

- 发现 → 实用工具 → AI 生图：Media 自己持久保存一个 `modelConfigId`，用户显式选择后才可生成，不自动选择首个资产。提示词最多 2000 字；一次生成一张，成功立即保存到系统相册 `Pictures/RavenCat`。生成失败显示脱敏后的服务端原文，保存失败保留暂存供显式重试；离开或进入后台取消请求并清理未保存图片，返回前提示丢失风险。
- `generate_image`：运行准备时固定同一份模型选择及连接，schema 与计费请求使用同一快照，避免运行中切换模型后参数契约错位。图片检查通过后沿既有 `createMediaAssetWithReference` 准备 backing，在同一事务检查 Chat／群任务 fence 并写入 `ai_generated_images`。只返回 `mediaAssetId`，由 `send_image` 发送或 `view_image` 查看，不自动创建消息。

未选择返回 `IMAGE_GENERATION_UNCONFIGURED`，所选资产删除、不完整或用途不匹配返回 `IMAGE_GENERATION_MODEL_UNAVAILABLE`。UI 与执行解析共用五态判定；资产变更由 Host 转发刷新。模型切换对用户页面在下次生成生效，对 AI 工具在下次运行准备时生效；不换模型、不重放计费请求。

AI 生成引用属于角色，参与完整媒体审计、targeted release、角色删除候选和备份。用户生成及聊天长按导出的相册图片属于用户，**不写业务表、不进入备份、不被恢复出厂或卸载删除**。聊天保存只读本地原图，不改变消息或私有媒体引用。相册原生模块只复制原始字节，GIF／WebP 不转为静态帧，不申请相册读权限。

168 新增生成引用和选择表；166／167 备份预检使用不含新表的旧引用查询，升级后才使用当前查询，不能以忽略缺表代替版本分支。

下载后可将返回的 `mediaAssetId` 交给 Chat 的 `send_image`，作为当前会话中的真实图片消息发送；下载本身不会创建聊天消息。图片消息直接引用同一素材，发送事实与预览由 Chat 的回合提交负责。

`download_image` → 现有公共 HTTPS/DNS/重定向边界 → 原生应用缓存暂存 → 文件容器与解码验证 → 事务外准备 backing → 同一事务提交 MediaAsset 与 `ai_downloaded_images` 业务引用 → 清理暂存 → 返回媒体 ID。

下载的图片不自动写入 MediaStore，也不会自动出现在系统相册或公共下载目录；用户可从聊天长按菜单另存到相册。下载记录属于角色，随角色删除撤销；媒体回收继续检查头像、各收藏库和历史消息等全部引用。删除收藏只撤销收藏引用，同一图片仍被下载记录或消息使用时保留文件。备份枚举下载引用，恢复出厂沿用全库与私有媒体根目录清理。

下载时可用 `file_name` 取便于检索的名字。`query_downloaded_images` 只查询当前角色自己的下载记录：`media_asset_id` 精确查询最多返回一张，或用 `keyword` 对保存的文件名做包含匹配（不进行图片语义搜索），二者互斥；都省略时浏览最近下载，没有日期筛选参数。浏览和关键词结果按下载时间从新到旧，每页默认 20、最多 50 张，通过 `offset` 和返回的 `nextOffset` 翻页。同一媒体 ID 的重复下载合并为最新匹配记录，返回媒体 ID、文件名、来源 URL 和下载时间，不读取图片内容。模型使用 `view_image` 确认内容，再复用 ID；历史离开上下文窗口或被摘要压缩后仍可查询既有下载。暂不提供用户私有素材管理页面；相册导出通过聊天图片长按菜单完成。

`query_generated_images` 只查询当前角色通过 `generate_image` 保存的成图引用，不包含用户生图页的相册输出。支持媒体 ID 精确查询、保存时文件名关键词包含匹配，二者互斥；都省略时浏览最近成图。浏览和关键词查询沿用默认 20、最多 50 张与 `offset`／`nextOffset` 分页，同一媒体 ID 只返回最新匹配记录，结果包含媒体 ID、文件名和生成时间。生成时建议显式传入有意义的 `file_name`；未命名的旧成图仍可浏览或按 ID 找回。不搜索生成提示词或画面语义，不读取图片文件，确认内容仍交给 `view_image`。

下载与生成工具可在保存时命名。图片工具包里的 `rename_own_image` 传入媒体 ID 和 `file_name`，`delete_own_image` 只传媒体 ID。两者在同一事务中检查执行资格，并处理当前角色在下载库、生图库里具有同一媒体 ID 的所有记录。只在聊天等场景拿到 ID、自己图库没有保存记录时，返回 `OWN_IMAGE_NOT_FOUND`。改名更新检索名称。`send_image.file_name` 仍只负责本次消息的显示名。删除提交之后由 Media 检查完整引用并回收无引用素材，其他角色的图库、聊天、头像与表情收藏仍可持有同一图片。表情收藏的名称和删除继续由 Stickers 的工具管理。

`view_image` 支持媒体 ID、用户头像、自己头像和以 ID/名称指定的其他 AI 头像；重名返回候选，ID 优先。默认头像使用实际打包资源。应用设置工具的 `get_group_avatar` 复用同一视觉读取入口，由 Chat 查询群头像并裁决成员可见范围，默认群头像读取实际打包资源。群成员回复可用已授权的下载、看图与自主换头像工具；副作用提交由 Host 调用群任务持久资格检查，终止后不能继续提交下载引用或头像修改。

Host 注入头像查询和当前角色的视觉路由；配置辅助视觉时返回视觉转述，否则通过 Agent 的工具附图契约把实际图片送到下一轮主模型。工具附图在完整 tool_calls 结果批次之后组装为模型观察输入，不产生用户 Chat 消息。GIF、WebP 与动态图片转为 PNG 单帧，并明确报告单帧限制；已绑定视觉模型失效或失败时返回明确错误，不绕过角色选择。

聊天图片的当轮说明、读取失败提示及历史原文投影均保留 `mediaAssetId`，模型可直接用于看图、换头像或 `add_own_sticker` 收藏。历史投影只列文件名与媒体身份，不读取图片，不改变会话列表预览；只有旧 URI 的附件不伪造媒体 ID。已经压缩成摘要的正文由模型生成，不保证保留每张历史图片的引用。

聊天视觉读取在文件边界校验真实容器、解码与单边 8192 像素限制，再准备静态帧；不使用相册提供的 MIME 猜测实际输入。超限长截图保留原文件和媒体 ID，本轮以明确的失败原因进入文字输入，并提示用户分段或缩小后重发，不把不可用原图反复传给接口。

聊天主模型的 HTTP 400 / 422 明确图片拒绝允许一次文字降级，去掉图片与「原图已提供」标记，保留图片说明和媒体 ID，要求模型明确没有看到原图；正常文字回复沿原 T3 提交推进回复游标。流式的 fetch 与 Android XHR 共用这一请求边界，不为认证、权限、配额或服务错误去图重试。`view_image` 的工具附图和辅助视觉请求禁用这一降级，保持真实视觉交付契约。

图片不存在、文件被移除、格式损坏返回工具错误说明。头像、背景与封面获取复用同一视觉链路；应用设置的图片准备通过 `commitCroppedImageSelection` 在事务外裁剪，再由业务 owner 同事务检查权限、执行资格和 CAS 并提交引用。原图不改写，裁剪暂存由入口清理，默认绘制背景不伪造图片。

`applicationSettings` 工具包允许各 AI 修改自己、当前主理 AI 管理其他 AI 和全局图片，取代原来仅换自身头像的工具。权限、默认读取和引用契约见[应用设置工具](../../../docs/application-settings-tools.md)。

## 出口与验证

- `@features/media`：媒体 command/query、稳定 DTO、Agent 图片工具与预期图片错误。
- `@features/media/composition`：仅供 Host 组装具体 catalog/backing/repository 及图片工具端口。
- `npm run verify:ai-image-tools`：归属、迁移、取消、视觉附图及引用行为。
- `npm run verify:web-tools-native`：原生私有下载与公共联网边界单测，不生成完整 APK。
- `npm run verify:gallery-writer`：相册模块编译及 MediaStore pending／发布、取消回滚、原字节复制和存储失败分类单测，不组装 APK。
- `npm run verify:backup-restore`：包括 166／167 预检、167→168 回滚及 168 生成快照恢复。

实际相册不可见性、默认头像读取与模型视觉输入仍需 Android 设备验收。

图片拒绝回归覆盖真实 BaseAIClient 的 complete、fetch stream、Android XHR stream，以及有 / 无工具、严格看图、认证 / 权限 / 服务错误与降级再次失败；尺寸检查覆盖 1080×20000 的长截图。辅助模型与图片工具专项验证已通过；真实视觉效果和原生设备行为仍需实际服务与设备验收。
