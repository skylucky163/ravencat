# 默认提示词组装

提示词中心展示的聊天上下文阅读顺序如下，各块按场景与启用条件注入：

普通单聊、群聊成员回复、账本回复与复用单聊的日程唤醒，段内顺序由 `shared/prompt/readingFlow` 同时供提示词中心和编译器消费。页面不再手写另一份顺序，编译器也不能用插槽分类覆盖中心的段内顺序。消息角色边界仍由编译器维护：固定背景在前置 system，历史保持原角色，本轮状态位于历史之后。中心显示的是共用主线，不是某一次请求的完整正文；通话和内部决策任务保留各自场景预设。

```text
基础规则（视觉规则按需）
→ AI 人设、当前昵称与对话者身份
→ 协议空间常驻提示词
→ AI 身份池
→ 群聊身份背景（仅群聊）
→ 全局常驻片段 → 满足条件的 AI 专属片段
→ 工具能力、用户特批工具、工具包用途目录
→ MCP 服务简介
→ 跨会话背景 → 本会话二级摘要与未归纳一级摘要 → 历史原文
→ 工具运行上下文（内部触发说明）
→ 用户状态与一起听
→ 时刻未读社交资料
→ 本轮环境（交互位置、触发来源、应用触发资料）
→ AI 当前身份状态（原主理 AI 冷静期等）
→ 被动记忆
→ 手机电量
→ 当前时间
→ 场景输出契约（内部规则，按场景出现）
→ 当前用户输入（应用触发没有新用户发言时省略）
```

首页的用户人设入口跳转「我 → 个人」资料页。对话者身份从同一份 user_profile 聚合用户名、性别、年龄、身份、地区、其他设定与签名；未填写字段不注入，其他设定保留完整正文。头像仍属于媒体展示，不把本机图片 URI 写进文字提示词。群聊名称采用参与者目录快照，新增资料不改变 mention 解析契约。

## 消息角色与信任边界

普通 Prompt Pack 的 `systemPrompt` 只包含前置系统内容。`modelMessages` 按以下顺序发送：

1. 历史 `user / assistant` 消息，保留原角色；应用事件保留明确的资料来源。开启消息时间戳时，在各条正文前另放 system 时间元数据。
2. 一条本轮 `system` 消息，包含工具运行上下文、状态、社交、环境信息、记忆、当前时间以及场景输出要求；没有内容时不创建空消息。
3. 仅有真实用户输入时追加当前输入；批量消息或图片由 Chat 的输入适配替换末尾输入，不改写历史后的系统上下文。

AI Client 只在最前面添加 `systemPrompt`。不再将本轮上下文提前合并进它，也不将时间冒充用户发言。工具续轮保留初始消息，再追加本次模型输出和工具结果，不重组第二份 Prompt。

消息时间戳在提示词中心「当前时间」下方独立开关，按 AI 保存于 `context.message_timestamps`，默认关闭，与当前时间注入互不依赖。开启后，历史与本轮真实聊天消息前由独立的 system 元数据说明该条记录时间，统一使用 UTC、精确到秒；元数据明确不属于正文或回复格式，不能再把时间前缀写入 assistant 正文作为可模仿的回复范例。正文、图片内容与原角色保持原样；时间不同的分段分别保留，不计算或注入时间差。页面说明用途、额外输入 Token 开销和模型仍可能模仿的风险。关闭后不再添加这类元数据；已有正文和摘要不自动清理或改写，既有摘要的讨论起止时间仍保留。

跨会话背景位于本会话摘要之前，本会话摘要是前置系统段末尾的历史资料。背景与其他前置内容不变时，新增摘要只追加在原有 system 末尾；摘要归纳、编辑或背景更新仍可能改变已有前缀，不保证服务商必然命中缓存。原文是独立消息，摘要和记忆中的正文保持资料语义。协议空间是用户与 AI 共同维护的固定提示词和信息，全部条目常驻注入，直到修改或删除；正文可以指导行为，但不能扩大工具权限或覆盖系统基础规则。

AI 日程自主执行没有新用户输入，复用普通单聊的前置 system、摘要与原角色历史。本轮环境说明日程到期与自主活动时间；日程事实进入动态 system，行动记录的输出语义进入输出契约。账本同样保持单聊位置，触发来源与账目资料在动态 system，账本回复要求进入输出契约。两者均不伪造末尾 user 消息；原有历史末条真实用户发言保留。

## 信息所有权与生命周期

- 固定背景：人设、当前昵称、用户资料、群聊成员和群内身份。事实更新才改变前置正文，昵称的历次修改不堆在身份背景中。
- 历史：Chat 按发生位置保存用户发言、AI 回复与用户操作／应用事件。昵称修改和一起听退出是历史资料，使用带明确来源的 user role；不占对话条数，随对应历史窗口与摘要交接，不因 AI 回复成功而消费。
- 本轮环境：Host 统一说明单聊／群聊／通话位置与用户输入／账本／日程等触发来源。交互位置、触发来源、冷静期可以同时成立，不是互斥场景枚举。
- 当前状态：一起听、电量、时间、冷静期按各自事实 owner 的本轮快照注入。一起听的播放、输出设备与歌词只在当前 AI 参与的活动为 active 时注入；普通播放、邀请待回应及退出后省略整块，邀请和退出仍保留在历史中。
- 规则：固定行为边界进入前置规则；账本和日程等本轮执行／输出要求进入历史后的输出契约，不混在资料正文里。

昵称设置与 Chat 操作事件在同一 databaseCoordinator 事务提交，SQL 各归所属 Feature；Host 只装配事务端口。提交后由 Chat 通知时间线与摘要 consumer。事件不会发起 canonical 用户回合，不影响回复游标；不存在待提醒标记或成功回复确认链。数据库 135 将旧昵称修改表迁为原时刻的聊天事件，已清除范围不复活。

## 条件与权限

本轮环境位于历史之后的动态 system，社交信息之后、被动记忆之前；普通单聊也明确说明当前位置。群聊身份背景独立位于前置身份层。用户当前昵称随人设注入，冷静期属于当前 AI 身份状态；昵称变更只走历史时间线。提示词中心分别展示这些用途与位置，不提供动态事实编辑入口。

社交盒子在普通单聊和群成员回复中均注入，只按当前 AI 的 `agentId` 读取其未读事件摘要，不聚合其他群成员的收件箱。摘要不包含时刻正文，也不标记已读；无未读时不注入正文。工具总开关关闭时仍提供摘要，同时明确说明用户未开启工具调用权限，当前不能读取详情或执行社交操作，不得声称已经完成。时刻正文与详情由 AI 通过已授权工具主动读取，可见性仍由 Moments 负责。

工具指引只消费上游已固定的本轮有效授权，不从星标、历史或产品身份推导权限。基础工具规则由 `buildToolsDescription(allowedToolNames)` 唯一生成，聊天、MCP-only 和自主任务共用，不在渲染时重新执行权限策略。拆包指导属于工具目录，具体调用指导属于各工具 schema：社交详情主动读取由 `getMomentDetail` 说明，自主解除的同意规则由 `release_host_cooldown` 说明。社交、冷静期、协议和群聊保密区块只提供自身事实与边界，不接收单项工具授权，也不拼接调用指引；社交区块仅依据已有的工具总开关说明关闭状态。群聊保密规则保持静态定义，目录、安全预览和真实运行使用相同正文。

群成员的身份上下文不负责授予或关闭工具。本轮工具总开关、AI 授权、主理身份和场景限制由既有执行链裁决，模型只按实际工具目录与 function schema 调用；群中禁止视频通话。群输出规则中的自然语言、JSON 与身份字段要求约束对外回复正文，不禁止已授权函数调用的 JSON 参数；工具同样不得用于泄露隐藏上下文或内部身份映射。身份上下文每轮动态生成，无需迁移数据库中的提示词正文，已有在途请求继续使用自己的快照。

摘要生成与已有摘要注入独立控制，按 AI 的 canonical 单聊保存。暂停生成且无固定起点时，历史原文使用最近 N 条逻辑消息；固定时读取从起点到最新的全部原文，并暂停生成。两种情况下已有摘要都由注入开关选择。仅关闭二级归纳时暂停新二级任务，恢复注入现存一级摘要。两级摘要请求复用聊天稳定前缀，只提供领取的来源与任务规则，不装载社交、被动记忆、电量、当前时间或普通聊天历史。详见[两级摘要契约](../architecture/chat-summary.md)。

AI 身份池是低频更新的固定身份背景，位于协议之后、自定义片段之前，不因运行时读取而后移。提示词中心的身份池入口管理全局入选名单：默认全部勾选，新增 AI 默认入选。未勾选的 AI 与身份池双向隔离：其身份记录不会注入其他 AI 的请求，它自己的请求也省略整个身份池块，不接收其他 AI 的名称、模型、数量或主理状态；重新入池后恢复相互可见，全部取消时所有 AI 均省略整块。每条入选记录包含 AI 名称、稳定身份键、底层模型名与身份／协作状态；名单不改变模型调用与工具权限。Host 随本轮提示词配置读取并冻结排除名单，在共用身份池块入口按当前 Assistant 实体键裁决接收资格；仅入池 AI 继续由 Assistants 身份目录统一筛选记录和统计，避免正文、主理名称或计数泄露被排除的身份。这一接收资格不依赖工具总开关或主理身份，私聊、群聊、通话、账本及自主任务均使用同一入口；窄内部任务继续使用自己的预设。配置变更对后续组装生效，不清除已有聊天历史或改写在途请求。

MCP 简介是独立能力块，位于内置工具目录之后、聊天摘要之前；不再和工具规则拼成同一块。只有 MCP、没有内置工具时仍提供该 AI 已授权的服务名称与简介。远端工具 schema 继续由 MCP meta-tool 按需返回，不改变执行授权。

协议空间同样不依赖工具总开关，在这些 AI 执行场景中完整注入。用户通过界面管理，AI 通过已授权的协议工具管理；不存在优先级或有效期筛选。旧预设的缺项和禁用不取消常驻注入，工具续轮仍使用本次快照，修改从后续请求生效。

视觉真实性规则只在本轮涉及视觉时出现，图片输入不关闭已授权工具。单聊与群聊共用工具说明、特批说明和用途目录的注入位置，旧群聊预设缺项不取消运行时目录。工具运行上下文在中心单列于历史之后；本轮回应要求在时间之后、当前输入之前，只展示用途。工具参数 schema 仍在请求独立的 `tools` 字段，不是普通 system 正文；时刻可见范围候选只随发布工具的 schema 提供，按 run 冻结，仅包含显示名称与稳定 agentId，不再另建聊天提示词块。实际可见性和发布资格仍由 Moments 应用层裁决。

普通工具默认开关与 AI 单项覆盖先确定授权候选，再由现有 runtime policy 裁决总开关、场景、身份与本轮能力。全局开启主理工具不授予普通 AI 主理身份。手机能力的开关由手机工具模块管理，提示词中心不再叠加第二份手机权限。

小红书文字笔记、网易云音乐等特定应用工具包另有独立的全局总开关，默认关闭。开关保存在 Prompting 的全局配置，在手机工具页管理。Host 生成授权候选时先排除未开启包的工具；用途目录、特批说明、拆包枚举和 schema 共用这份结果，不在各层重复读取设置。关闭不删除单项偏好、星标或已保存的展开状态；重新开启仍需通过身份与单项授权，变更不改写已开始运行的冻结快照或已有聊天历史。

工具包详情的星标是每位 AI 独立的直接暴露偏好，默认关闭。Host 在一次运行开始时冻结配置，仅从本次已授权工具中选出「用户特批工具」；首次请求及工具续轮直接提供这些工具的 schema，不要求拆包，也不受 AI 收起工具包的操作影响。关闭调用权限时不暴露，重新授权后星标仍保留。特批说明位于固定工具目录前、聊天摘要之前，只列工具名与常驻说明，不重复放入待拆包目录。

工具包用途目录只包含包 ID、标题、简洁的包级用途和本次已授权且需拆包的工具名，不包含逐工具 `description` 或参数。包级用途帮助模型选包，工具名提示本次可用能力；具体工具说明与参数仅由请求 `tools` 字段中的 function schema 提供。拆包状态由当前 schema 和拆包工具的 observation 表达，不再另存一份动态 Prompt 状态表；拆包不改写已编译的本轮上下文或固定目录，schema 仍随实际暴露能力变化。

`open_tool_package` 打开工具包，`close_tool_package` 在不再需要时收起。普通单聊随正式回复保存开关，持续保留到主动关闭，不需要每轮续期；同一轮先开后关或先关后开按实际执行顺序提交。其他运行只在当前 run 生效。两个控制工具的包 ID enum 来自同一份固定授权目录，不因开关状态重写。收起只影响下一次请求的需拆包 schema，不取消当前批次已经接受的工具调用，也不能撤下特批工具或扩大权限。

正常工具续轮只在原始消息后追加模型输出与工具结果，不注入逐步递减的额度提示。次数限制由 Runtime 执行；仅在工具阶段确实结束或完成前需要受限补充时追加对应机器指令。消息前缀稳定不等于服务商必然命中缓存，变化的 schema 与服务商缓存协议仍需单独验证。

## 工具总开关与抓包核验

工具总开关属于每位 AI 的模型配置。关闭后，本轮有效工具集合为空；单项权限、星标和已保存的拆包状态都不能覆盖总开关。配置变更对后续准备的请求生效，已经开始的 run 保留其冻结快照。

| 请求部分 | 总开关关闭时 | 总开关开启时 |
| --- | --- | --- |
| 基础工具规则、工具运行上下文 | 不注入 | 本轮有有效工具时注入 |
| 用户特批工具、工具包用途目录 | 不注入 | 仅从本轮有效授权中形成；星标只决定是否直接暴露 schema |
| MCP 服务简介、MCP meta-tools | 不注入 | 按 MCP 服务、AI 关联和 grant 冻结可用集合 |
| 请求顶层 `tools`、`tool_choice` | 不发送 | 只发送本次可见 schema；普通未拆包工具不直接发送 |
| 社交摘要、昵称、冷静期、用户状态、协议、记忆、时间、电量 | 继续按各自条件注入 | 同左，不介绍具体工具 |
| 历史消息、摘要、人设、用户自定义正文 | 不过滤或改写其中的工具文字 | 同左；用户片段的 `tools_enabled` 条件仍由总开关控制 |
| 通话中的查看画面工具 | 不发送，走普通流式回复 | 沿用通话专用 `lookAtUser` schema；通话不再强制覆盖总开关 |

普通单聊与群聊第一次请求的消息排列如下，缺失或关闭的区块直接省略，不搬动后面的区块：

1. 第一条 `system`：基础规则（正文非空时）→ 换行规则（开启时）→ AI 人设、当前昵称、用户资料 → 协议 → AI 身份池 → 群聊身份背景 → 全局与 AI 专属自定义片段 → 工具基础规则 → 特批工具 → 工具包目录 → MCP 服务简介 → 跨会话背景 → 本会话二级摘要及未归纳一级摘要。
2. 历史原文：保留真实 `user / assistant` 角色；历史工具记录保持历史资料语义。
3. 本轮 `system`：工具运行上下文（仅有有效工具时）→ 用户状态与一起听 → 当前 AI 的未读社交摘要 → 本轮环境与触发资料 → AI 当前身份状态（冷静期）→ 被动记忆 → 电量 → 当前时间 → 场景输出契约。群聊保密规则位于输出契约，不携带调用说明。
4. 当前 `user` 输入：真实正文、图片/附件输入或同批输入；无 OCR 的直传图片附件可附带已开启的图片防幻觉提醒。账本与日程等应用触发不创建此消息。
5. 发生真实调用后的续轮：完整保留上述消息，再追加本轮 `assistant.tool_calls` 和相应 `tool` 结果；普通正文中写出函数名或 JSON 不构成调用。

`tools` 是请求顶层的独立字段，不是 `messages` 中的一段文字。首次请求只包含特批工具、先前保持展开的工具及必要的包/MCP 控制工具；拆包续轮可以改变 `tools`，不重写已冻结的消息前缀。全部工具均特批时没有空的拆包控制入口；仅 MCP 时不虚构内置拆包入口。

稳定前置内容只有其事实或配置发生变化时才改变；新增动态状态、时间及当前输入在历史之后。新增摘要接在稳定前置内容之后，摘要归纳或编辑会改变摘要段。保持顺序和前缀为缓存提供条件，不保证具体模型服务商的命中结果。

通话及内部决策任务保留各自预设顺序：通话的口语场景、视觉事实和输出契约仍在原位置，仅撤去未授权调用指导；挂断/拒绝跟进和 OCR 等窄任务继续使用独立契约。两级摘要沿用现有聊天稳定前缀，但请求不执行工具，也不装载普通聊天的动态状态与历史原文。提示词中心的安全预览只展示静态正文和动态块摘要，不代替实际网络请求；抓包以上述 `messages`、`tools` 和 `tool_calls` 为准。

普通回复的时间开关按 AI 保存在 `assistant_prompt_definition_states`，默认开启。关闭一位 AI 的时间块不影响其他 AI，也不关闭自主执行所需的机器时间。

换行规则 `output.paragraph_breaks` 复用每 AI 的开关与正文覆盖，默认关闭。开启后仅在普通聊天、群聊、记账回应与日程消息的稳定前缀中注入，紧随基础规则、位于 AI 人设之前；工具续轮沿用首轮正文。列表只保留跳转入口，开关在正文编辑页管理。通话口语、摘要和内部 JSON 任务不使用这条规则。原独立 `foundation.visual_grounding` 块已移除；图片防幻觉提醒 `input.image_grounding` 改由聊天附件输入组装层在无 OCR 的直传路线中按开关追加，默认开启。识别失败仍使用原有失败说明，不叠加提醒。

视觉识别正文 `internal.vision_ocr` 位于 `vision.ocr` 窄任务的稳定部分，输出契约 `output.vision_ocr_plain_text` 锁定，只允许纯转述正文。正文按「AI 覆盖 → 全局默认 → 内置正文」解析，由 Host 在发起识别请求前读入并交给块构造，不进入普通聊天。绑定视觉识别模型后聊天图片改走转述路线，主模型只收到 OCR 文本；未绑定时原图直传并改用图片防幻觉提醒。该正文此前按 OCR 辅助模型配置保存（`metadataJson.taskPromptOverride`），现已统一由提示词中心管理，历史记录不再读取，也不做迁移。

手机电量同样按 AI 保存，定义为 `context.device_battery`，默认开启。Host 在配置解析后仅为开启的 AI 读取一次 Android 电量与充电状态，放入动态后缀并紧邻当前时间；工具续轮复用同一份快照。关闭时不读取也不注入；系统未提供有效电量时不生成该块。聊天、群聊、通话、账本和自主任务共用这一条组装路径，电量不属于一起听的状态所有权，也不触发自主唤醒。

用户状态与一起听（`context.user_state`）和时刻社交信息（`context.social`）同样是按 AI 保存的注入开关，默认开启。前者关闭时，一起听运行时块（`context.together_listening_runtime`）不参与本轮组装；后者关闭时，时刻 Social Inbox 既不查询也不注入。两者都只影响提示词注入，不改变一起听活动本身或时刻的可见性规则。

## 边界与验证

全局默认配置属于 Prompting。配置写入不包含模型请求或跨 Feature 副作用，排序交换通过同一 SQLite transaction 提交。不会自动裁剪提示词或历史来符合 token 阈值。

`scripts/verify-prompt-context-lifecycle.mjs` 覆盖单聊、群聊身份、冷静期、账本和日程的实际装配；`verify-assistant-nickname.mjs` 覆盖事件原位、窗口、摘要、并发与事务回滚。`scripts/verify-prompt-overview.mjs` 覆盖请求顺序、批量输入、工具续轮、中文及配置继承、真实 SQLite 保存与排序回滚，以及默认组件的编辑、重置、开关和导航操作。
