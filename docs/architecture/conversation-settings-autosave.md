# 个人主页与对话设置自动保存

## 入口与范围

AI 个人主页（`/assistants/[aiId]`）由单聊消息 AI 头像或「更多 → AI 个人主页」打开，顶部栏显示「AI 名称的主页」，资料卡集中展示头像、「公开名称（专属昵称）」及设定前 300 个 Unicode 字符，超出时追加省略号；未设置昵称时只显示名称。资料卡右上角编辑图标跳转独立页面 `/assistants/[aiId]/edit`，名称、昵称与人设分开修改，点击「完成」等待保存后返回主页。用户头像保持不可点击，消息多选时不打开主页，协助回复按实际消息归属打开对应 AI；不存在的 AI 展示不可用状态。读取期间发生的资料提交事实优先于较早的查询快照。
个人主页提供模型设置、上下文设置、聊天摘要和朋友圈入口。上下文设置（`/assistants/[aiId]/context-settings`）集中编辑注入条数、固定起点和历史群聊；原对话设置位置只保留一个指向同页的入口。「更多」保留原名片和菜单，对话设置继续编辑流式、多气泡、行动步骤和 Token 显隐，以及原背景与铃声。流式与多气泡本轮不变；旧 Chat 设置地址继续只做替换跳转。
聊天背景与通话背景继续由原有组件及命令独立提交。群聊信息保持现有流程；管理员配置遵循 [模型设置自动保存](model-settings-autosave.md)。

- 名称与人设失焦时保存，停输不提交；正常保存不提示成功、不自动返回。
- 独立编辑页提供 AI 昵称，沿用相同自动保存节奏；去除首尾空白后最多 20 个 Unicode 字符、只允许单行，空值清除备注。仅用户可写，AI 只能读取自身昵称。用户界面优先显示昵称，公开名称字段及模型成员目录继续使用原名。
- 四项上下文条数同样失焦提交；主条数为正整数，客条数允许 0。多气泡开关立即提交自己的字段，不带走尚未失焦的文字草稿。主题不支持分段时仍保留用户选择。
- Token 用量与行动步骤开关独立、立即保存，默认开启，只影响当前 AI 的单聊展示，所有主题均可自由开关，切换主题保留选择。行动步骤同时控制思维链、工具状态与自主活动过程，不影响正文或其他业务系统消息；两种开关均不改变模型请求、消息存档或用量记录。
- 空名称显示字段错误并保留草稿；写入失败保留草稿，提供重试和恢复已保存值。
- 单聊头像选择或恢复默认后立即提交；失败保留头像草稿并在头像区域显示错误。
- 名称、人设和头像按字段独立提交，空名称不影响人设或头像保存。人设可留空清除，正文保留输入排版。助手头像命令不接收名称或人设。
- 编辑页的按钮返回与系统返回统一由 App 路由的 `usePreventRemove` 承接，先等待头像操作并提交资料修改；未保存的无效输入或头像草稿会阻止返回。Feature 不另注册系统返回处理。
- 对话与模型设置继续由原表单的 `useAutoSaveNavigation` 处理按钮及 Android 返回，新外壳不叠加第二套返回拦截。普通返回回到实际来源，不固定跳回更多菜单。
- 固定消息起点入口复用同一离开流程，保存成功后由 App 显式进入目标 AI 的消息列表。固定期间保留近期条数原值并暂时禁用“单聊·主”；起点与摘要开关按当前 AI 的 canonical 单聊独立保存，详见[摘要与固定范围](chat-summary.md)。
- 名称草稿与数据库确认分开，旧确认及头像更新不覆盖用户的新名称输入。

主页的「朋友圈」进入 `/assistants/[aiId]/moments`，复用 Moments 时间线组件。它以用户视角读取该 AI 稳定 `agentId` 的动态，在 Repository 的 SQL 分页前筛选作者，评论和点赞仍由用户命令提交。顶部采用该 AI 的资料和默认封面，不挂载用户封面编辑控制器；空列表保留刷新入口。

## 所有权

「流式输出」由每个 AI 的对话设置拥有，复用与多气泡相同的开关交互。未手动选择时，daylight、night、liquid-glass 默认关闭，moon-kimi、paper-note 默认开启。开启使用流式，关闭使用非流式，操作后独立即时保存，手动选择跨主题保留；页面不展示第三种选项。

偏好保存于 `ai_assistants.streaming_reply`：NULL 为跟随主题，1 为流式，0 为非流式。页面请求与普通聊天执行宿主均在装配本轮配置时解析该偏好，模型页不编辑或重置它。在途回复保持原策略，下一轮（包括显式重新生成）读取最新选择。流式不覆盖主题的多气泡支持及用户的分段选择；两项同时开启时，当前气泡逐步出字，在自然边界闭合后继续下一泡。非流式在完整生成后按相同边界分段，并保留原交付间隔。

Assistants presentation 负责只读主页、独立编辑页、资料输入校验与头像草稿，App 负责具体导航动作和系统返回拦截。Chat presentation 分别负责上下文草稿和对话页面偏好，各自拥有交互节奏、输入校验与离开行为。通用草稿确认使用 shared/ui 的 AutoSaveDraftEditor；每份草稿只包含当前页面真正编辑的字段。
助手资料由 Assistants 命令与 Repository 更新；主页、编辑页与朋友圈共用 `useAIAssistantProfile` 查询并订阅既有资料更新事实，Chat 的助手列表及当前聊天分别消费同一事实。当前聊天只合并匹配 AI 的持久化配置，保留会话、菜单、到达预览与置顶投影，列表旧快照不回填模型或展示配置；不创建第二份资料或改写聊天会话身份。
上下文、气泡与展示设置由 updateAIAssistantSettings 提交到助手字段；显示选择保存于 ai_assistants.show_token_usage 与 show_action_steps，不参与模型调用。模型页不编辑或重置这些对话字段。主题只提供行动卡片外观，不裁决这两项显隐。
名称只提交 name，人设只提交 systemPrompt，头像只提交头像引用。主页通过助手提交事实同步资料，草稿确认只推进本次已保存字段；对话设置沿用增量提交，不通过设置页面回调给 Shell 回填整份资料。
昵称只提交 nickname；Assistants 在事务内读取真实前值，Host 将当前值更新与 Chat 的操作事件组合提交，相同值不新增事件。当前昵称属于前置身份背景，修改事件固定在聊天时间线，随窗口和摘要消费，不再由最终回复确认或消耗。
人设仍保存于 ai_assistants.system_prompt，由 Assistants 命令经 databaseCoordinator 提交；提示词中心与后续提示词组装直接读取同一数据库字段，不复制第二份人设。提示词中心的人设详情仅展示，重新获得焦点时读取最新正文。
头像文件草稿继续由 usePersistentAvatarDraft 管理，媒体引用创建及 CAS 保留原来的事务边界。

对话、上下文与单聊摘要页面共用 `AssistantConversationPage`，只查询目标 AI 的既有 canonical 会话，固定起点与背景键都属于该会话。它不调用 `usePreparedConversation` 或会话创建命令，也不读取全局当前会话来猜目标；仅查看设置不切换聊天、不推进已读或预加载消息。助手或会话不存在时展示不可用，读取失败提供重试，不创建替代会话。

摘要的主页入口与更多入口打开同一个 `/chat/[aiId]/summary`。摘要列表、编辑、二级正文、任务与设置都按同一目标会话读取，不切换当前聊天；原生成和保存流程不变。

## 验证

`npm run verify:assistant-profile` 验证名称与昵称合并展示、独立编辑路由与完成返回、AI 朋友圈资料与路由、资料事实同步、编辑页返回拦截、读取失败与重试，以及迁移后的名称、人设和上下文失焦保存、多气泡立即保存、无效条数拦截、清空人设、写入失败保留草稿、空名称与头像独立更新、头像错误重试及恢复、返回等待和恢复默认头像。
`node --no-warnings scripts/verify-prompt-overview.mjs` 验证人设只读展示及重新获得焦点后的数据库同步。
模型自动保存回归确认迁移到 shared/ui 后的行为保持不变；助手 Repository 验证头像提交不覆盖名称或模型配置。
`node --no-warnings scripts/verify-moments-timeline.mjs` 验证 AI 作者筛选先于分页、混合作者不漏页和删除游标行后的续页；`node --no-warnings scripts/verify-moments-loading.mjs` 验证 AI 头像与默认封面，以及 AI 朋友圈不读取用户封面或提供用户发布入口。
`npm run verify:assistant-settings` 验证主页设置入口、独立模型页、正式和旧地址、Host 装配、对话目标与背景键，以及提交事实到当前聊天的身份隔离。原有自动保存专项继续验证错误草稿、离开前提交和固定起点的保存屏障。
不构建 APK，原生相册与真实键盘交互需要真机确认。
