# Chat 展示与中断历史

本协议不改变普通聊天的 Android execution host、T1～T4 revision、T3 原子提交或媒体物化所有权。

## 事实与所有权

`ChatAgentTimeline` 按收到的真实事件分配 source sequence。`ChatTurnPresentation` 合并同一条目的最新版本，最多每 80ms 写一批；实际工具开始前等待一次短小的快照事务，保证崩溃后不会自动重放已开始的工具。执行不等待 UI、展开操作或原生分段间隔。

持久展示消费者在批次边界只物化变动条目，不按 token 重算整轮快照或序列化旧正文。canonical 分段的发布、返回版本和完成判断共用一个短事务，消费者使用该事务返回的版本更新投影。分页窗口由挂载的会话列表持有；最后一个列表卸载即释放，迟到读取不得写回新窗口。没有页面的恢复读取只保留本次读取期间的临时状态。

同一分页窗口的展示历史、同一页面的重写状态各自最多一个读取在途。事实事件在读取期间到来时使旧结果失效，并合并为最新状态的补读；展示历史还需保留本批显式要求的中断回合。合并属于投影 owner，不在 SQLite 调度器中猜测业务查询等价性，也不缓存已完成的数据库结果。

列表只在消息窗口更新后请求展示历史，不再重复订阅聊天事件。消息事实由时间线订阅读取，运行结束和中断由展示 owner 主动重读；不能在同一事件到来和消息读回时各触发一次历史查询。自主回合的来源消息按会话与 client identity 共同关联，沿用消息复合索引，不扫描其他会话的消息。

共享 Agent 展示 store 按 run 保存当前投影来自执行器还是历史回填。历史读取只回收已离开窗口的历史来源投影；群聊等执行器产生的实时片段不属于单聊展示表，不能因历史查询没有返回该 run 而被清除。执行与历史更新沿同一身份交接来源，不另建消息缓存或重放队列。

`chat_turn_presentations` 属于 ConversationTurn 的展示状态，不是执行队列。`chat_turn_display_items.snapshot_json` 保存最新收到版本，`shown_json` 保存已经交付给会话时间线或后台收件箱的版本。正文尚在流式组装或等待分段时钟时只保存原始快照，不能伪装成已交付。

交付必须先持久化、后更新展示 store。已经允许界面展示的正文、思维链和工具记录因此是稳定事实，后续新输入不能撤销它们。折叠、展开、滚动、屏幕测量和页面卸载均不裁决内容是否保留；UI 绘制不是执行事实，也不是本轮交付完成的门槛。

聊天页由 `useAgentTransientTimeline` 统一投影持久消息和运行片段的到达资格，再合并时间线。只有已通过到达投影的 canonical 行能够确认并清理对应运行片段；SQLite 先读回、原生到达快照稍后同步时，已经显示的气泡必须连续保留。不能先确认原始查询结果、再在下一层隐藏 canonical 行，否则会制造气泡消失与重现的交接空窗。committed replacement 的未到达尾段同样不提前显示。

`messagesReloadRequested` 默认是当前窗口的事实重读，不是重新进入会话。订阅提供当前已加载消息身份，Repository 在同一 SQLite 快照内选出其中仍存在的最早持久 ID 并重读其后消息；不存在持久身份时才读取首屏。乐观 ID 不作为数据库边界，不通过保留已删除实体来维持位置。普通重读不修改历史分页的 generation、requestId 或向前游标；清除全部历史在 commit 后显式携带 `resetHistory`，由窗口 owner 同步撤销旧请求所有权、游标与缓存，再读取清除后的事实。首屏、分页、刷新及增量查询的迟到结果都不得写回旧窗口。

过程卡片的全部已交付子项可随时重新展开，不需要用户逐项滚动才能存档。中断片段按当前历史窗口读取，既不把负数展示 ID 放入消息分页，也不一次注入全部旧运行历史。canonical 与运行片段混合时，展示排序用 source sequence / segment，返回的持久消息游标不变。

群内工具提交的成员／群名变更提示携带发起回合身份，作为独立业务消息立即可见。展示分组将同一段行动过程中产生的这类提示放在该行动卡下方、下一条真实发言之前；后续思考与工具过程继续更新原卡，不用成功提示切出新卡。用户操作、其他回合、真实发言仍划分行动边界。关闭行动步骤或本轮中断不能隐藏已经提交的操作提示。该规则只改变 UI 分组，不重写业务消息、模型上下文或分页游标；缺失归属的旧记录不按相邻消息推断。

正文按稳定 identity 使用原生到达时钟，尚未交付时不渲染占位气泡。后续 reasoning / tool 不等待这条正文；出现真实正文时按源顺序切分行动步骤。工具提案、实际开始和完成分别记录，工具返回给模型的实际结果随快照保存，不把未知结果写成成功。

流式多气泡与最终提交共用单向分段规则：空行闭合当前泡；长段达到 100 字符后，在下一个完整句末闭合，不为了凑长度回头搬动句子。句末连续标点与引号、括号可以跨 delta，末尾尚无后文时继续保留在当前泡。只有活动尾泡持续增长，已闭合泡不在后续增量中重复写入；模型终态到达后，仅更新状态和真实用量，不重新分段。

生成中的正文通过同一持久批次直接交付，不再叠加非流式的原生分段间隔。展示 owner 记录本轮已进入流式展示的 source sequence，后续闭合和 T3 仍沿用这些气泡身份，不重播到达时钟。非流式完整正文保留原生分段节奏；两种方式均先保存交付版本，再更新展示投影，关闭与恢复边界不变。

完整正文气泡的持久发布同时取得通知资格，不等整轮工具完成或 T3。活动尾泡闭合前不按 delta 通知；用量更新与 T3 绑定同一 `clientMessageId` 时不重复通知。通知和悬浮预览仍经统一交付协调器裁决；未闭合尾泡、中断后迟到版本与恢复读取均不产生补发通知。

AI 日程使用同一展示、行动步骤和 T3 提交，不把正文映射为过程记录；工具前言也属于普通正文。已经流式交付的 identity 在 T3 只绑定正式消息，继续正常交付回调，不重新申请发布资格或提前收口其他分段。静默控制信号是唯一的正文策略差异，不撤回此前已展示的内容。

自主回合没有对应的新用户输入，历史窗口和中断上下文按隐藏的触发来源消息定位，不借用用户回复游标。响应与终态从共享回合和展示事实读取，摘要同样按共享展示状态保护尚未结束的范围，不依赖额外的开始、响应或结束聊天说明。旧独立行动记录仍按自身历史证据读取。

每次模型请求返回的真实 token 与缓存统计随该次正文的交付快照保存，多段正文只在尾段承载一次，与 T3 正式消息保持相同归属。实时前言和 T3 后分段都不能等历史读回再补统计；T3 前中断与进程重建保留已交付版本中的用量。流式正文早于供应商统计到达时不估算数据，收到真实统计后更新；缓存命中为零与未提供保持区分。

Chat 回复 Flow 生成的运行编号同时进入工具上下文和消息元数据，主动回复也遵守这一归属。工具成功、失败都由行动步骤承载；已有记录缺少运行身份时，按单条工具记录独立成卡，不根据相邻正文猜测或回填所属运行。

原生发布资格随单次展示注册与释放，注册先于持久 open，结束、宿主撤销或 Native Module 销毁时释放。未知和已释放的 run 默认拒绝到达与通知，迟到的关闭回滚不能重新注册；因此不需要永久保存旧 run 的关闭记录。并发 T1 仍分别持有关闭引用。会话时钟只保留在途使用者与最近一个分段间隔内的空闲项，移除空闲时钟不得拆开仍有等待者的 Mutex。

## 事务与中断

T1 前暂停旧批次放行并保存已有执行事件，不等待模型或分段 timer。T1 原事务区分两种事实：旧 run 尚在执行时只停止后续执行，保留已交付前缀；旧 run 已 committed 时将其剩余 canonical 分段一次放行，并将展示状态设为 completed。提交失败恢复原批次。提交后通过一次原生桥接清除这批消息的内存 pending 过滤，不等待旧分段间隔。

T3 一次写入其余 canonical 项、绑定已提交媒体与稳定片段，并发布最终过程记录。展示资格不改变回复游标：T3 前停止保留独立运行片段和已发送媒体，不把旧 run 伪装成整轮成功回复；T3 后用户新输入只加速交付，不撤销成功事实。超时、宿主销毁和进程突然死亡仍封闭未交付尾部，不能自动补发。

`chat_visible_messages` 是普通历史、预览、未读和模型上下文的 canonical 可见读取边界。已交付完整项可读取 canonical 行；部分版本保留为独立运行片段。未交付 canonical 行不因清空内存 pending、重进页面或进程重建而自动可见。停止执行不插入“执行已中断”“回复展示已中断”等替代气泡，也不把已完成行动步骤替换成中断提示。

失败／取消／中断不回滚已发生的工具业务效果。工具开始标记存在的崩溃孤儿收口为 failed，不隐式重跑；结果未知不能写成成功。语音等 prepared backing 仍只在原 T3 中物化，失败时沿原 Media 回滚清理。

显式重写仍遵守替换契约：失败时撤销尝试投影、恢复原回复，失败尝试不作为普通 `user_reply` 执行历史注入模型。它不改变普通新输入保留旧过程的规则。

图片、表情在工具完成后经当前回合 fence 提交正式消息，并在同一事务发布完整可见版本；不等待后续模型请求。消息保持 run 归属与稳定身份，T3 只绑定最终顺序，不再次交付。失败、取消、supersede 和进程重启保留已经提交的媒体；原消息被用户删除时，T3 不从内存意图中重建。语音暂存 backing 与重写媒体仍在 T3 取得正式消息后进入原持久交付流程。展示表只引用已物化媒体，不提前接管 backing。

`select_sticker` 工具只返回选择意图；Chat 完成输出事务后，工具记录才说明媒体消息已提交。续轮失败不能把已发送媒体标成未发送，原错误气泡只反馈后续失败；取消和被新输入替代不报成执行故障。取消识别只接受明确的取消异常，不因 Provider 或 SQLite 错误正文包含 `aborted` 而静默跳过失败反馈。T3 事务抛错仍保有原 fence 内的错误反馈资格，不能在事务返回裁决前用本地 settled 状态压制错误；已经提交的媒体与整轮完成是不同事实。

中断上下文从持久交付版本读取正式媒体元数据，并标明 `committedMessage`，而不是仅凭“工具选择成功”推断已发送。即使进程在输出事务之后、工具完成投影确认之前死亡，下一轮仍能读取实际发送事实，不能自动重发。执行宿主、原生发布资格和通知裁决保持原 owner。

后续普通单聊经 Chat 查询读取当前上下文范围内的独立执行记录，按原输入位置插入已交付前言与真实工具结果，明确它们是历史资料。执行记录通过 role=user 提供，并标明是应用附加资料、不是用户新请求或助手回复；不能把内部 JSON 包装成 role=assistant 的历史发言，诱导模型模仿内部记录格式。原任务仍在未消费输入区间时，由固定输入组装器保持“原任务 → 已发生结果 → 新输入”的真实顺序，普通历史不重复注入；原任务已成为历史时，由 Host 历史装配插入。不得构造缺少配对调用的 role=tool，不重放工具，不推进游标，也不把思维链全文重复注入模型。旧记录未保存的工具返回值不能凭空恢复。

## 验证

运行阶段与最后事件时间随快照同批持久化，来源仅限模型请求开始、收到输出、工具实际开始／完成和终态事件。T3 原事务将阶段推进到交付；它不代表 UI 已经呈现。请求宿主的 receipt 使用独立 request revision 与输入高水位记录，不改变执行 revision；迟到启动拒绝不得覆盖新请求或撤销新 owner。

T1～T4、宿主回执、运行进度与展示收口在持久事实变化后发布 `turnExecutionChanged`。状态消费者只监听该事实事件，并合并在途读取期间的新请求；消息刷新与 typing 动画不再各自触发执行状态查询。

普通聊天页只将进行中的真实阶段投影在标题原来的名字位置；完成、失败和中断均恢复名字，不把终态永久挂在标题。失败原因继续保存于持久状态与诊断，模型失败沿用原有错误处理，不新增标题兜底或替代气泡。回前台与重进页面重新读取。不显示“多久无新事件”，不注册状态刷新计时器，不查询网络连通、不充当心跳、不驱动执行或重试；宿主启动成功也不等于模型已经收到请求。SQLite 读取失败记录诊断并恢复名字，不能据此宣告 run 已失败。

`verify-chat-turn-presentation.mjs` 验证持久版本与关闭边界；`verify-chat-agent-display-integration.mjs` 使用真实 Runtime、事件队列、Projector 和 SQLite，覆盖两轮工具、中途 supersede、T3 后分段中断及独立子进程重读，并验证启动回执竞争和实际运行阶段。`verify-chat-execution-status.mjs` 使用真实 React 验证异步读取隔离、前后台重新读取与页面重挂载。原生 `TurnDisplayProgressTest` 验证关闭后拒绝迟到到达与通知发布。

Android 页面展开、滚动、前后台切换及真实绘制仍须真机验收。静态检查和 Robolectric 不能代替 Protected Contract 规定的后台连续三次验收；普通聊天宿主保障见[生命周期协议](./chat-background-execution-lifetime.md)。

### Android 验收矩阵

使用包含两个模块原生改动的已安装版本，分别在 Android 13 与 Android 14+ 验证。模型可使用 Kimi K3；工具只操作专用测试数据。记录 runId、revision、输入高水位、最后事件、展示 state、每项 version / shown_version 和业务副作用，截图不能代替数据库事实。

| 场景 | 必须观察的结果 |
| --- | --- |
| 两轮以上 reasoning → assistant → tool，首条正文仍在等待交付 | 后续 reasoning / tool 及时出现，顺序锚点稳定，Runtime 不等待分段时钟 |
| 行动步骤始终折叠、从未展开或滚动 | 全部已交付过程照常保存；正常完成后运行状态清空 |
| T3 前快速连发两条用户输入 | 已交付版本和完成工具保留；没有中断替代气泡，下一轮上下文包含真实结果 |
| T3 后第一段已显示、其余分段待交付时输入 | 剩余分段立即一起出现，committed 和游标不回退，展示状态 completed |
| 上两种情形后退出重进、结束进程再打开 | 可见事实一致，没有重复工具；超时／进程死亡未交付尾部仍隐藏 |
| 工具业务已提交但尚未收到完成事件时杀进程 | 副作用保留；孤儿失败，结果未知，不自动重放工具 |
| 慢首响、断网、VPN 各自单独测试 | 慢请求显示等待模型响应；失败沿用原有错误处理，标题恢复名字；不能把 VPN 故障当作宿主冻结 |
| Home 后保持后台、屏幕关闭、Overlay OFF / ON | 独立宿主均能运行；回复落库、通知与点击返回符合原协议；连续至少三次通过 |
| 原生启动被系统拒绝、通知权限关闭 | 拒绝保留 pending 与启动失败诊断并沿用发送错误提示，标题恢复名字；权限关闭不创建第二宿主或页面执行 |
| 群聊、主动消息、悬浮回复、语音／表情与重写 | 原通知裁决、身份、上下文、媒体所有权和原子替换均不回归 |

SQLite 发布提交和 UI 绘制并非原子操作；恢复依据持久交付事实，不以绘制猜测模型是否仍在运行。数据库 133 修复旧版扣留的过程记录及误判为展示中断的完成回复，不补发未完成正文、未物化媒体或超时关闭的尾部。
