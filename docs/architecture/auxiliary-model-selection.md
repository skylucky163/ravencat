# 辅助模型资产与业务选择契约

辅助模型中心上层管理服务配置，下层按用途管理摘要、embedding、OCR、生图、STT、TTS、translation 模型。服务只拥有地址、认证方式与凭据；用途模型拥有模型 ID、任务参数和业务类型。模型资产不再提供启停开关，可用性由类型与连接完整性决定。

服务分组保存在 `model_service_groups`，拥有配置名称、共享地址、固定认证方式和下一默认编号；`model_service_configs` 每行对应独立 Key，保存稳定连接 ID、分组引用、Key 名称、原始编号与凭据。摘要、向量、视觉、AI 翻译、自定义 OpenAI 兼容 TTS、角色与群管理员通过 `service_config_id` 引用具体 Key，不引用组名、URL、显示编号或数组位置；已绑定的行不保存连接凭据副本。完整连接由组地址、认证方式和 Key 凭据共同组成，分组内的凭据及编号受 SQLite 唯一索引保护，跨组完整连接去重与写入共享 coordinator 独占事务。认证方式创建后固定，更换方式需新建配置。STT、官方 TTS 和腾讯云机器翻译继续独立保存连接与凭据，不选择、不关联、不自动收录通用服务。

默认开启「自动保存服务配置」，由 `model_service_settings` 保存。有效模型配置写入时在同一事务查找完整匹配的具体 Key，已有连接直接复用，新连接收录为单 Key 分组；不只根据 URL 合并用户分组。关闭后，新连接只保存在当前配置；既有 Key 仍可选择和引用。模型新建表单、输入过程和连接测试不创建服务；不完整的连接不自动收录。

服务创建一次事务保存整个分组与全部 Key；编辑分组名称／地址及各 Key 的名称／凭据分别自动保存，互不携带其他编辑器的旧草稿。Key 名称选填，空值展示其原始编号；分组的下一编号只递增，移除其他 Key 不改已有编号。未保存的空槽位不生成记录。已有服务选择与快捷填 Key 共用「选择模型连接」弹窗：分组标题以上下两行显示配置名称和地址，可展开／收起；展开后缩进显示上下排列的 Key 名称与完整密钥，只有具体 Key 可点选。每次打开统一收起所有分组。选后显示「配置名称 · Key 名称」。服务绑定选中态只比较稳定连接 ID；模型发现按当前 Key 发起，切换 Key 会清空旧列表并撤销旧列表请求的发布资格。

角色与群管理员保留自己的模型和生成参数，选择 Key 只填入连接。在用途或角色页改地址／凭据，只为当前用途重新绑定，不修改原服务；在服务管理页改组地址影响组内全部 Key，改某个 Key 仅影响它自己的引用。改名称不回写旧凭据，修改连接保留全部稳定 ID 与绑定。删除 Key 时，在同一事务撤销摘要与向量旧请求资格、解除它的用途／角色／群管理员引用并清空继承连接，再删除 Key；删除分组对组内全部 Key 执行相同操作，任一步失败全部回滚。SQLite 外键保持启用。角色、模型参数、业务选择和历史数据保留，失去连接的资产不可调用，只有用户主动设置连接才能恢复。跨 owner SQL 由 Host 通过各仓储的事务入口组合。

服务命令以事务提交为写入成功边界；提交后的监听器或角色投影读取失败只返回刷新提示，不能使页面误报未保存。资产信号逐个通知消费者，单个监听器失败不阻断其他消费者。角色刷新使用删除事务返回的受影响 ID；模型中心与群管理员页面消费资产信号重读数据库，草稿继续遵守已有增量与外部刷新契约。写入异常只在服务命令边界归类，页面与日志不接收原始凭据。

单聊与群聊的摘要模型持续引用 `summary` 资产，一级、二级共用 `modelConfigId`。空引用明确表示当前聊天模型或群管理员；连接或调用参数变更与旧请求资格撤销共享事务。修改共享服务时，同时撤销显式摘要资产和跟随角色／管理员的在途请求资格。正文、处理进度和引用 ID 均保留，不自动替换模型。一次性应用上下文设置仍只复制四项数值，与连接复用无关。

实际使用的模型由对应业务保存配置 ID。支持首次初始化的全局业务在首个资产可用后一次性初始化尚未配置的选择；摘要不参与首次初始化，Memory 的向量化仍由用户主动开启。角色 OCR 与 TTS 只由用户手动选择，新建角色和创建模型都不自动绑定，已有选择原样保留。

## 1. 选择所有权

| 使用方 | 持久化 owner | 选择入口 |
| --- | --- | --- |
| 记忆向量化 | Memory：`memory_model_settings` | 记忆设置中的通用开关与独立模型选择，全部空间共用，关闭时仍可配置模型 |
| 聊天与通话图片预处理 | Chat：`chat_assistant_image_settings`，按角色保存 | 当前角色模型设置弹窗 |
| 聊天录音、通话 STT | Speech：`speech_recognition_settings` | STT 模型列表顶部直接选择 |
| AI 语音消息、通话 TTS | Assistants：`assistant_voice_settings` | 当前角色模型设置弹窗 |
| 聊天消息翻译 | Integrations：`translation_settings` | 翻译模型列表顶部的「聊天翻译模型」选择 |
| 表情包识别、向量化 | Sticker 自有配置 | 表情包系统已有弹窗 |
| 用户与 AI 文生图 | Media：`media_image_generation_settings` | 发现 → 实用工具 → AI 生图；同一份持久选择供页面和 AI 工具使用 |
| 时刻图片理解 | Moments 自有配置 | 时刻设置已有选择 |
| 单聊／群聊两级摘要 | Chat：`chat_summary_request_settings`，按来源会话保存 | 聊天摘要设置中的总结模型 |

连接信息、密钥与模型资产只保存于辅助模型中心，业务配置不复制它们。
Host 装配资产查询与模型调用端口，不把 Repository 或 SQLite connection 交给其他 Feature。
所有选择保存后立即影响下一次任务；正在执行的任务遵循原有生命周期。

## 2. 解析与状态

`resolveAuxiliaryModel` 只解析调用方传入的配置 ID，没有默认、继承或自动挑选候选的分支。
`getAuxiliaryModelSelection` 返回候选与当前引用状态，和执行解析共用可用性规则。
删除、能力类型不匹配、连接信息或语音、翻译 Provider 配置不完整时，显示不可用原因。
当前引用独立于候选列表读取，因此删除或连接不完整不会被误显示成未选择。

业务选择保留失效模型的 ID，用于展示原因；用户取消选择才清空。
可用表示本地配置满足调用条件，不保证实时网络、鉴权或额度正常。请求失败由原有调用链处理。
模型资产变更提交后发布变更信号，由 Host 通知对应设置投影刷新。

### 2.1 全局首次配置与角色手动选择

Assistants 在 `auxiliary_model_initial_defaults` 按能力记录首个配置 ID 和初始化完成标记。它只用于创建时初始化，不参与任务解析，也不保存连接信息。

- 首个资产与默认记录、各 owner 的初始选择在同一事务提交；失败全部回滚。主键与事务保证并发创建只有一个首次模型。
- 首个配置凭据未填完整时暂不生效；该配置后续可用时完成一次初始化。第二个模型不会抢占首次身份。
- OCR 只初始化 Moments 与 Sticker 识别选择；STT、translation 初始化对应全局选择；embedding 只初始化 Sticker 向量选择。角色 OCR、TTS 与 Memory 不参与。
- 全局与 Sticker 只填空引用。完成标记阻止后续创建或编辑重放初始化；默认记录保留资产删除后的 ID。
- 新角色的 OCR、TTS 均未选择；创建、补全或编辑模型不会回填角色绑定。既有绑定（包括失效引用）与显式取消保留，只有用户选择或取消时才改写。
- `image_generation` 不参与首次资产初始化。只有一个可用模型也必须由用户在生图页显式选择；取消后不会被新增资产回填。
- Host 只组合各 owner 的事务入口。事务内只写 SQL；commit 后复用资产刷新信号与 Sticker 队列唤醒，Memory 的指纹、revision 与 claim 仍由原队列处理。

STT、TTS、翻译和生图的提供方在创建后不可修改；四类编辑页统一只读显示提供方，模型、名称、凭据和同提供方参数仍可编辑。更换提供方需要新建资产，再由使用处明确选择。仓储在已有更新事务中读取当前身份并与下一份配置比较，使用 Speech、Integrations、Platform 各自的 metadata 解析契约，不按地址或模型名猜测；拒绝发生在服务绑定与消费者失效之前，不增加另一套回滚或恢复流程。无 metadata 的旧 TTS 保持既有兼容协议，旧自定义生图资产保留记录并提示新建。

固定提供方的生图与官方 TTS 表单在 Key 输入框右侧提供「＋」，按当前实际地址从所有已有服务分组选择 Key；只忽略首尾空白和末尾斜杠，协议、域名、路径仍需相同。语音实际地址复用 Speech 的解析，选择时重读凭据并确认源地址未变。该操作只填入 Key，不填源地址、模型和参数，不指定源 Key 引用；生图保存仍遵循原有完整连接收录契约，官方语音仍独立保存。ASR 使用专用语音连接与认证，保留只读地址与手填凭据，不提供通用 Key 的「＋」入口；火山 ASR 提示填写语音控制台 API Key。腾讯云签名凭据不参与 API Key 填充。

语音提供方与参数契约归 Speech，Assistants 的语音表单和资产可用性解析复用同一校验。官方语音地址在 Key 上方以只读字段展示，与 Key 匹配及请求配置共用草稿解析，随站点和工作空间参数更新；只有自定义兼容服务允许编辑地址，已有非官方地址由用户明确决定是否更换。测试调用读取当前合法草稿快照，不提交选择、消息或媒体资产。Chat 语音工具在 run 准备时固定角色 TTS 快照及支持的表达参数，避免工具 schema 与执行模型在用户切换配置后错配。当前提供方与扩展入口见 [Speech README](../../src/features/speech/README.md)。

通用 `ConfiguredModelPicker` 只负责展示与交互，查询、保存和刷新信号由 owner 提供。
所有模型选择弹窗统一使用 `ModelPickerModal`，`ConfiguredModelPicker` 只持有业务选择状态。业务模型选择在固定底栏左侧取消选择、右侧管理模型；空列表或读取失败时仍可进入管理。点击管理先关闭键盘和弹窗，待弹层移除后调用点击时保存的导航意图，防止清空弹窗类型后跳错用途。Feature 通过共享导航 context 表达用途，Host 映射到辅助模型中心对应用途列表；已经在目标管理页时不重复压栈。生图沿用路由适配的未保存图片确认，不再单独显示管理按钮。配置编辑中的接口型号列表不重复提供管理入口。说明文字收进标题旁的公共问号 helper，弹窗与列表复用主题材质。模型变更信号刷新通用选择器的候选与当前引用；时刻设置返回时重读当前模型，表情包沿原有焦点快照刷新，均不自动更改业务选择。

## 3. 消费行为

- 生图资产复用创建与自动保存，供应商保存在 metadata。硅基流动／MiniMax／Seedream／千问／OpenAI 使用各自已声明的图片协议，固定官方地址与已适配模型列表；自定义 OpenAI 入口和能力开关已移除，不猜测协议或补发探测请求。旧自定义资产保留原 ID 和内容，UI 与 resolver 明确报告不可用，需要新建供应商明确的配置；读取确认供应商、地址、模型匹配。只有新建阶段可切换供应商并清空旧 Key 和服务绑定，表单不从通用服务填入任意地址。本次比例、清晰度、格式、压缩和参考人像由 Media 页面拥有，不回写模型资产；Z-Image 仅提供文字生图与图片比例。表单「检查配置」不发聊天或生图请求。执行固定一次连接／协议快照；失效时明确失败，不回退到聊天或 OCR。每次执行只发一个计费请求，等待窗口为 180 秒；官方 GPT Image 可在该请求内接收真实中间预览，取消与最终事实仍由原来的 Media／Chat fence 持有。相册和私有媒体的所有权见 [Media README](../../src/features/media/README.md)。

- Memory 全部空间共用开关与模型选择，关闭后保留模型并可继续配置，选模型不自动开启。记录、编辑、关键词检索与触发词召回不依赖模型。开启且模型可用时生成向量；切换与关闭仍经过原有模型指纹、revision、claim 与队列取消契约，UI 不直接创建向量任务。
- Memory 设置提供独立红色「清除已有记忆向量」，确认后只清除派生向量和任务状态，保留开关与模型选择。Host 取消并等待旧请求，Repository 原子清除并撤销 claim；清除不立即重建，后续在开启状态下新增／编辑记忆或切换模型时生成。普通关闭保留已有向量，重新开启统一重建。模型切换后的状态同步和逐条重建交给前台交互空闲队列，不在选择操作中处理整批记忆。
- 每个角色独立选择视觉识别模型，模型选择本身就是图片路线，不再另设预处理开关。
- 未选择或取消选择时，原图直接交给当前聊天模型，由用户确认该模型支持图片；不使用能力标记或模型名白名单拦截。
- 选择后先识别，再把文字转述交给聊天模型；所选模型失效时进入 `vision_unavailable`。识别请求失败时由 Platform 统一分类，HTTP 408／504 或明确超时错误向主模型说明「OCR 超时，未获得图片内容」，其他错误说明 OCR 失败；原始报错不进入模型输入，不自动改为直传。整轮取消或宿主截止时直接结束执行，不把取消转成 OCR 失败后继续请求主模型；OCR 没有独立计时器。
- 通话图片继续复用 Chat 的图片输入解析，不建立第二套图片模型选择。
- 聊天录音和通话共用 Speech 的 STT 选择，consumer 标签不产生额外配置层。STT 列表内嵌现有选择控件，原「我 → 语音识别设置」入口与页面已移除，已有选择无需迁移。
- STT 空选择提示配置模型，失效引用提示检查或重新选择。Speech 拥有统一转写会话与具体错误展示，不因模型失效或请求失败自动切换服务。
- TTS 只读取当前角色的手动选择；取消或未选择时不可用，不跟随其他角色或运行时默认。
- 聊天翻译入口先显示 `translation` 模型列表，AI 与腾讯云配置共同展示，列表内直接选择聊天翻译使用的配置。资产管理复用 Assistants，实际选择仍由 Integrations 保存，无独立设置页。提供方契约归 Integrations，资产可用性解析与输入校验复用同一契约。AI 翻译复用 Platform 的 OpenAI 兼容客户端，不限制模型名；翻译提示词只消费原文，不继承聊天上下文。所选模型失效时明确失败，不自动挑选其他资产或提供方。

## 4. 升级与备份恢复

迁移95在同一事务内：

1. 把旧启用的 embedding、OCR、STT 选择转到各 owner 的配置。
2. 保留角色明确的 TTS 选择和停用状态；把原先继承的旧全局 TTS 一次性固化为角色选择。
3. 保留失效引用，不根据候选自动选模型。
4. 删除 `capability_bindings` 和 `assistant_capability_bindings`，提交 `PRAGMA user_version = 95`。

旧版 OCR 角色绑定先由历史迁移88转换图片策略，再进入此次迁移；历史多模型冲突仍不武断选择。
转换失败则整个事务回滚，包括版本标记；修正失败原因后可完整重跑。
后续启动与新版快照恢复按版本标记跳过旧绑定表的创建与转换，不重写用户的新选择。
新 schema 不包含旧绑定表，数据库备份格式仍为完整 SQLite 快照，版本标记与业务选择一并保存。

旧 capability binding 的运行时继承、默认 UI 和全局绑定 API 不再存在。首次初始化写入各 owner 的明确选择，不恢复旧绑定表或运行时继承。
历史升级脚本仅服务旧数据库升级，不提供运行时兼容回退。

迁移96在同一事务内，把旧 Chat 全局视觉选择复制给原先开启预处理的角色，保留失效引用；原先直接传图的角色保持未选择。随后删除旧 `chat_image_settings`，提交版本96。旧 `image_processing_mode` 列仅用于历史升级，不再进入角色实体、设置草稿或运行时判断。新角色的视觉模型保持未选择，删除角色时选择随身份级联删除；重启和快照恢复不重放旧开关。

迁移106在同一事务内将 `external_service_configs` 中的翻译记录转换为 `translation` 资产，保留凭据、参数、启停、名称与时间戳，并将原来实际使用的配置固化为 Integrations 的明确选择。历史退休的 `translate` 资产不恢复使用。仅删除已经转换的外部翻译行；其他历史服务行不在迁移范围。失败时全部回滚；版本标记随选择进入备份，新版启动与快照恢复不重放迁移。

迁移108只记录每种能力按创建时间最早的旧资产，并标记已有安装的首次初始化完成，不回写旧业务选择。角色创建不再消费这些记录；资产不可用或删除时不自动选择第二个。迁移 marker、资产 ID 与业务选择一并进入完整 SQLite 快照，重启与恢复不重放初始化。

迁移152为 Memory 增加独立 `embedding_enabled`，旧引用非空时保留开启，空引用保持关闭；模型引用（包括失效引用）、正文和已有向量不变。新安装默认关闭，后续开关与选择分别持久化，重启和快照恢复不重放启用逻辑。
