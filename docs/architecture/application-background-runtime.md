# 应用级持续后台运行

## 唯一所有者

`modules/background-runtime` 拥有通用前台服务、独立总开关和应用执行宿主。
开关位于「小程序 → 权限与后台运行 → 持续后台运行」，默认关闭，原生持久保存，恢复出厂关闭。
开启后 `RavenCatBackgroundService` 跨消息、会话和页面持续运行。消息结束和功能开关无权停止它。
系统仍可停止或回收进程；START_STICKY 与回前台 reconcile 只恢复用户开启意图，不重放业务。
只有实际进入前台服务后才报告 running=true；启动拒绝或五秒回执超时向调用方报错。
通知的停止动作关闭同一个总开关。普通回复通知继续归统一 delivery 协调器。

## 一个 RN 执行身份

原生 `ApplicationExecutionHost` 直接启动应用 ReactHost，桥接建立后持有唯一的
`RavenCatApplicationExecution` RN 后台运行身份。这个身份随总服务运行，与消息数量无关。
JS 注册项只返回一个等待原生结束的 Promise，不轮询、不运行空循环，也不占用 CPU 锁。
总服务停止时由原生结束身份；如果实际通话仍持有媒体执行资格，沿用同一身份直到媒体服务结束。
不使用 `HeadlessJsTaskService`，也不依赖它的跨 Service 非计数框架锁或完成协议插件。

聊天、身份回应、日程、悬浮消息、通话和两类通知动作均进入同一原生信箱，再由
`src/host/runtime/ApplicationExecutionHost.ts` 分发到原有业务用例。信箱只跨越桥接初始化，
不持久化、不重放已经取走的请求，也不是第二份业务恢复队列。JS 先监听、再连接并取走请求。
消息不再创建 Android Service、RN task 或逐消息启动回执。

总开关关闭时，前台仍使用现有应用 runtime；后台触发只尽力使用系统授予的窗口，
不另起短期服务或逐请求 RN task。没有持续后台保证，不能承诺熄屏或进程回收后继续完成。
聊天未完成事实由 SQLite claim / fence 与既有恢复入口裁决，禁止页面 fallback。

## 业务预算与执行资源

每次请求仍有业务身份、取消与预算，这些是业务边界，不是独立保活服务。
原生使用单调时钟计算截止，桥接等待也计入预算；JS 只接收剩余时间，向业务传递 signal 与截止点。
聊天和身份回应九分钟、悬浮请求十分钟、日程十一分钟（含 Worker 取消宽限）、通知动作三十秒。
通话由媒体终态结束，不规定任意通话总时长。Worker 继续等待本次回执，不因总服务延长系统预算。

`ExecutionWakeLocks` 管理一把共享 CPU 锁，只在实际请求或媒体执行时登记，空闲不持有。
完成与到期只归还本次登记，不停止总服务，也不撤销其他业务的执行资源。
Chat 的 T3 截止检查、T4 撤销与提交 fence 继续拥有持久化正确性；底层忽略 abort 也不能迟到提交。
关闭总开关不取消已经提交的业务，也不替代其持久状态。

通话媒体、悬浮 UI、设备控制继续由各自功能服务拥有，平台权限和功能终态仍在原层处理。
网络协议、Provider 重试与消息事实提交不属于保活模块。

## 验证边界

本地行为测试覆盖多条消息共享一个 RN 身份、消息不启停服务、桥接前投递只消费一次、
等待预算、媒体延续同一身份、旧桥接销毁隔离、共享 CPU 锁和总开关启动失败。
JS 测试覆盖各业务分发、等待完成、取消与归还；Chat 测试继续保护 T3/T4 和交付语义。
设备仍需验证连续聊天后 Home、熄屏、总开关与功能组合、通知停止、进程回收和权限关闭。
原生模块变化需要更新安装包；本任务不构建完整 APK，本地测试不能代替设备验收。
