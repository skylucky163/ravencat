# AI 回收站

## 生命周期与所有权

Assistants 持有 `ai_assistants.deleted_at`，原助手 ID、不可变 `agentId` 和全部从属数据保持原位，不复制第二份归档。正常资料、列表、身份目录和设置写入仅访问未回收助手；回收站使用独立查询读取删除时间与头像。

删除入口将 AI 移入回收站，保留完整 168 小时。重复删除不刷新时间。恢复只接受尚未到期的回收记录；彻底删除使用读取到的 `deleted_at` 在删除事务中再次匹配，已恢复或进入新一轮回收的记录不能被旧清理批次删除。到期与恢复以单写事务的实际顺序裁决。

UI 入口为「设置 → 数据管理 → AI 回收站」，由 App 路由适配导航，Feature 只接受返回与打开意图。回收站展示明确到期时间，恢复与彻底删除都需二次确认；功能说明放在标题旁的说明气泡，正文不常驻解释。

## 可见性与历史保留

回收期间隐藏 AI 的个人资料、单聊、私聊收藏、记忆、协议、通话记录、自己的朋友圈及个人管理入口。各业务数据继续由原 Feature 持有，媒体引用也保持有效，不因隐藏释放文件。

以下历史继续可见，彻底删除后也保留：

- 群聊中已经发生的消息；
- 其他会话中保存的消息分享和朋友圈分享快照；
- AI 在用户或其他 AI 的朋友圈中留下的评论、回复和点赞。

Moments 在分页前排除回收作者自己的动态；单帖、AI 查询和社交未读使用同一可见性条件。其他动态上的互动不按互动作者过滤。恢复后自己的动态重新出现；彻底删除时删除原动态及其从属互动，不改写外部动态。分享保留发送时的快照与独立媒体引用，不能因原帖或 AI 消失而丢失图片。

## 事务与执行资格

Host 将跨 Feature 具体实现装配到 Assistants 的运行时网关。移入回收站的写事务同时：

1. 保存回收时间，撤销主理与记账身份；原主理进入既有任命冷静期。
2. 由 Chat 撤销单聊回合、展示及摘要 claim，取消尚未领取的用户输入和重写请求。
3. 将该 AI 未完成的群聊发言任务置为跳过，保留成员关系及设置。

提交后才中止进程内请求、结束相关通话、撤销通知并刷新 UI；原主理的 Companion 与未来日程沿用既有身份撤销流程。新的 Chat claim、群聊领取和模型摘要排除回收助手，迟到结果继续受原有 run、revision 或 generation fence 约束。持久交付后才到达的旧消息不再弹出通知或悬浮内容。

恢复沿用原身份和会话，不自动恢复主理或记账权限，不重放回收前排队或正在执行的回复、群聊发言及主动任务。成员原有设置保留，之后发生的新聊天可以正常参与。

彻底删除在同一事务收集即将消失的媒体引用，清理该 AI 的个人数据、自己的朋友圈和日程，再执行既有助手与单聊级联删除。提交后交由 Media 按所有真实引用裁决释放；共享快照、其他会话或其他人的引用继续保护同一资产。

## 任命关系与 AI 知情

回收时间与主理冷静期分别保存，时间均正常流逝。再次回收一个已处于冷静期的普通 AI 不重新开启或延长冷静期；恢复也不改写全局冷静期。原主理恢复后，在仍为有效冷静期对象且已授权工具时，继续获得 `release_host_cooldown`；回收期间的迟到调用不得解除。解除不授予主理身份，仍由用户任命。彻底删除原主理也不会提前解除全局冷静期。

恢复在主理身份串行边界内完成，只恢复数据，不继承主理或记账身份，也不改动其他 AI 的现有任命。记账队列沿用当前任职者查询和原有聊天取消边界，不因恢复重新授权旧角色。

回收和恢复各自产生一条持久的应用操作事件，与状态变更共用写事务。事件只记录移入或移出回收站的动作；回收时按实际撤销情况附上「主理 AI 身份已移除」「记账 AI 身份已移除」标记，不在历史中解释冷静期、工具或任务规则。操作人名称、AI 展示名称和被移除角色在提交时保存快照；Profile 的事务内名称查询只执行 SQL，不解析头像或封面。用户页面显示「你将 xxx 移入了／移出了回收站」，模型历史显示「xxx 将你移入了／移出了回收站」，用户给 AI 的备注不进入模型事件正文。Chat 将事件作为应用历史资料进入上下文与摘要，不冒充用户口述，不改变聊天预览，不推进用户回复游标，也不强制唤醒模型；当前主理资格与剩余冷静期仍由每轮动态身份信息提供，历史文本不能授予权限。事件写入失败时整次操作回滚，提交后再刷新消费者。

## 到期维护与恢复

Host 在数据库就绪后维护一个最近到期时钟，并在助手生命周期变化、启动和回到前台时重新对账。空回收站不轮询，不为清理创建 Android Service 或 RN 执行身份。进程未运行时不强行唤醒设备，下次启动清理已到期项；到期后即使文件尚未物理清理，也不能恢复。

维护任务纳入 Host 已有 reset/restore drain；停止后撤销订阅和计时器，不跨新数据库 generation 继续调度。回收时间和被隐藏的数据随整个数据库快照备份，恢复备份后仍按原删除时间计算期限。

验证入口：`npm run verify:ai-recycle-bin`，覆盖真实 SQLite 的隐藏、恢复、七天边界、失败回滚、任命不继承、冷静期与解除工具、清理与恢复竞争、待执行回复取消、共享媒体保护、旧库升级，以及页面与维护时钟的行为。`npm run verify:assistant-nickname` 同时验证用户操作历史中的回收恢复知情记录进入上下文与摘要，不伪造用户输入或改变预览。
